# 2026-10-04 — читабельність суперника й контакт стоп

**Хто:** Santos · T1 Дедал (координація) · T2 Гефест (камера та контакт) · T3 Архімед (дослідження) · T5 Арес (межі камери) · T4 Феміда (аудит) · T7 Кліо (журнал).
**Контекст:** Santos відповів «go» після передачі попереднього зрізу. T1 продовжує вже дозволену роботу над видимістю героїв і природністю руху; цей журнал відокремлює намір від перевіреного результату.

## Що обговорили

- У попередньому зрізі далекий суперник виглядав замалим, а контакт стоп із поверхнею лишався недосконалим — [[2026-10-04-T1-Playable-Water-Slice|попередній журнал]].
- Ціль лишається MacBook Air M3; 8 GB пам'яті — робоче припущення за словами Santos. Хмарний рендер не підтверджує продуктивність цієї машини.
- Зміни виконують паралельні ролі з окремими файлами; запуск Godot серіалізує T1.

## Що вирішили

1. **Камера:** T2 спочатку вимірює читабельність і кадрування; T5 визначає обмеження. За переданим T1 рішенням T5: лише для `behind`, нижня межа FOV 38°, плавна активація на 6–12 м, номінальний захист ближнього бійця 28% висоти кадру та м’яка ціль далекого 12.5%. Це **попередні дизайн-числа для перевірки**, не доказ досягнутої читабельності. Поточні жорсткі межі й захисні поля кадру зберігаються; старі критерії не послаблюються.
2. **Контакт:** T2 досліджує обмежену презентаційну корекцію за фактичною геометрією взуття у `CROUCH` та Choko `crouch_light`. Повітряні пози, піднята нога й книга не мають ставати помилковою опорою. Корекція не пересуває `Fighter` root і не змінює бойові дані — [[ADR-004-Physics-Is-Presentation]].
3. Обсяг і власники зафіксовані у [[Plans/2026-10-04-Camera-Foot-Contact|плані T1]] зі статусом `approved`; незалежне приймання належить [[Audit/2026-10-04-Camera-Foot-Contact|аудиту T4]]. Цей журнал не підміняє їх.
4. Нові платні генерації, покупки, публікація збірки й мердж у `main` до цього зрізу не входять. За повідомленням T1, GitHub API тепер відповідає 200; це ще не факт створення PR.

## Уточнення Santos — неперервний ракурс і відчуття удару

Нове пряме доручення Santos зафіксоване у прийнятому [[ADR-020-Camera-Continuity-And-Impact]]. Після дешу повз суперника камера зберігає неперервний світовий бік; розворот героя не запускає автоматичного розвороту кадру на 180°. Це уточнює попередню вимогу завжди бути позаду P1. Соло отримує обмежене випередження середнього горизонтального руху пари; shared PvP лишається симетричним. Напрям керування та бойові позиції від презентаційної осі не залежать.

[[2026-10-04-Camera-Impact-Readability|Дослідження T3]] наводить перевірені першоджерела про групове кадрування, smoothing, lookahead і подієвий імпульс. Вони обґрунтовують механізм, але не універсальні числа чи гарантований емоційний ефект. Рішення та реалізація — [[2026-10-04-Camera-Readability]] і [[2026-10-04-Camera-Impact]].

Акцент удару — детермінований зсув із межами 0.10 м по горизонталі, 0.06 м по вертикалі та поверненням у нуль до 0.24 с; числа **PLACEHOLDER до художнього приймання**. Він не витрачає global RNG, не змінює FOV, шкоду або hitstop. `impact_scale` 0–1 є параметром вузла; пункту меню налаштувань для гравця цей зріз ще не додає.

## Фінальна локальна перевірка

T7 звірила завершені логи поточного зрізу; проміжні числа вище лишено як історію:

| джерело у `contact-camera/` | результат |
|---|---|
| `logs/final-check-playable.log` | smoke **164 checks / 19944 frames**, **13 scenarios / 0 failures**; ERROR/WARNING у цьому логу немає |
| `logs/final-gates.log` | **БАТАРЕЯ ЗЕЛЕНА** |
| `final-regression/foot.log` | **462 checks / 0 failures** після lifecycle guard; замінює проміжні 460 |
| `final-regression/impact.log` | **25 checks / 0 failures**; без ERROR/WARNING |
| `logs/camera-idle.log` | **2847 checks / 0 failures** після виправлення тестової пози |
| `logs/camera-idle-render.log` | **2862 checks / 0 failures** із native capture; лише попередження про непідтримувану зміну V-Sync |
| `logs/impact-corrected-render.log` | **26 images**, `IMPACT_CAPTURE_COMPLETE`; лише V-Sync warning |

Ранній helper помилково задавав `INTRO` числом `0` замість іменованого `IDLE`; виправлено позу й приховано вступний банер. Актуальні метрики — з `camera-idle.log`: у 1152×648 висота далекого IDLE-героя на 12 м зросла приблизно **47.8 → 71 px**, на 20 м — **32.5 → 54.5 px**. Це замір конкретного кадру, не універсальна частка за всіх поз і дистанцій. За оглядом T1 кадрів до/після перетину камера зберігає світовий бік, обличчя P1 після перетину видиме.

Попередній impact capture мав некоректну камеру й **відкинутий як візуальний доказ**. Актуальний `impact-corrected-render` показує відповідь на синтетичне повідомлення про влучання, **не реальну колізію атаки**; `damage=95.0` у sentinel не змінює цієї межі. Відчуття удару в керованому бою ще не доведене статичним capture.

Фінальний незалежний висновок публікує T4 у [[Audit/2026-10-04-Camera-Foot-Contact|аудиті]]. PR ще створюється; посилання додається лише після успішної публікації. FPS M3, повна анатомія, ручний огляд камери, online та багатоворогове кадрування цим прийманням не підтверджені.

## Що відклали / відкриті питання

- Остаточний діапазон і активація камери залежать від вимірів та рішення T5; збільшення героя не має обрізати бій.
- Обмежена корекція стоп не означає повного terrain IK, реактивної стійки чи симуляції м'язів.
- [[ADR-017-Post-Ragdoll-Position]] лишається окремою системною роботою.
- Відчуття руху, звук на слух і фактичні FPS на M3 потребують окремого приймання.
