# Меню та HUD: доступна геометрія

T2 Гефест, 2026-10-04. Окреме доручення Santos на реалізацію після аудиту onboarding.

## Причина та виконання

`TextureRect` портретів 1024×1024 та іконок 512×512 успадковували натуральний мінімум текстури. `custom_minimum_size` не є верхньою межею: меню і HUD виходили за viewport навіть за коректного масштабування полотна. У двох фабриках встановлено `EXPAND_IGNORE_SIZE`; PNG не змінювалися.

Початкове вікно тепер 1152×648 — поміщається на екрані 1280×720 із запасом під декорації ОС. Базове полотно лишається 1600×900, режим `canvas_items/expand` незмінний. Resize дозволений; це не реалізація мобільного UI або перевірка HiDPI.

Іконки S1/S2 мають подвійний контур і слот `max(28, ceil(22 / s))` за [[06-UI-UX]]; перераховуються при resize. Проміжок між скілами — 4 од. Ширина під число кулдауну зарезервована, щоб таймер не зміщував сусідні ресурси. Текст статусу обрізається у виділеній ширині, не розсуваючи панелі. Бойові значення й механіка не змінювалися.

## Аудит і погляди

Звірено обидві фабрики, реальні PNG, full-rect сцену меню, сигнали кнопок, секцію display та вимоги [[06-UI-UX]]. Зовнішні аудити T2/T8 показали причинність intrinsic minimum, але не довели помилку системного DPI чи глобальний блок input.

Варіанти: A — незалежний від PNG мінімум та збереження стилю; B — додаткові wrappers/clip; C — зменшення PNG. Обрано A: усуває клас дефекту без втрати якості ассетів. Контури і розмір слота беруться з чинного GDD.

Погляди: гравець мишею бачить усі цілі; клавіатурний гравець активує видимий фокус; мале desktop-вікно поміщається на екрані; майбутній великий PNG не змінює layout; супровід отримує перевірку реального viewport input замість `pressed.emit()`.

## Регресія та негативний контроль

Предмет: для всіх перевірених desktop-аспектів меню має видимі кнопки з дієвим viewport input, а дві ресурсні панелі HUD не виходять за viewport і не перетинають таймер.

`tools/ui/layout_check.gd` інстанціює реальні сцени меню й арени у `SubViewport`, чекає відкладене сортування контейнерів, змінює logical canvas 1600×900 → 1600×1200 → 2134×900. Це bounded logical layout, а не вимір фізичного вікна. Перевіряє всі 10 кнопок, mouse та Enter з одним callback і реальною зміною вибору, портрети, HP, meter, чотири іконки, таймер і повні панелі; повторює HUD після широкого тексту кулдауну 99.9.

Команда з кореня репозиторію:

```bash
"$GODOT_BIN" --headless --path game --script "$PWD/tools/ui/layout_check.gd"
```

Умова проходження — `UI_LAYOUT PASS`, rc0. На провалі перевірити конкретний прямокутник чи callback у логу, не підміняти geometry прямим emit.

Три незалежні форми пошкодження в пам'яті (tracked код не мутується):

```bash
"$GODOT_BIN" --headless --path game --script "$PWD/tools/ui/layout_check.gd" -- --break=portrait
"$GODOT_BIN" --headless --path game --script "$PWD/tools/ui/layout_check.gd" -- --break=icon
"$GODOT_BIN" --headless --path game --script "$PWD/tools/ui/layout_check.gd" -- --break=input
```

Після першого `make check` T1 виявив застаріле очікування 17 контурних елементів у `_check_hud`. За окремим розширенням власності цей розділ `SmokeTest.gd` оновлено до 21 (17 попередніх + 4 іконки). Додано перевірку чотирьох унікальних канонічних PNG, незалежного від PNG мінімуму, вкладеності обох кілець та їх реєстрації; чинна перевірка кольорів і ширин тепер охоплює всі 21 елемент. Незалежні приклади GDD перевіряють слот 28/28/28/51/88 од. при масштабах 1.2/1/0.8/0.4333/0.25 та поріг 22 px. Інші секції smoke не змінювалися.

Кожна негативна команда повинна дати `UI_LAYOUT FAIL`, rc1: великий мінімум портрета, великий мінімум іконки, недоступна для натискання кнопка. Додатково обов'язкові `make check` та `make gates`; централізований запуск координує T1, щоб не створювати паралельні Godot-процеси.

## Межі перевірки

Централізований прогін T1 на Godot 4.7: `playable/logs/ui.log` містить `UI_LAYOUT PASS (0 failures)`. Три негативні логи `ui-negative-{portrait,icon,input}.log` містять очікуваний FAIL: 36/22/6 порушень відповідно; T1 підтвердив rc1 кожного. `playable/logs/check.log` містить `ALL OK (164 checks)`, включно з оновленим контрактом 21 контуру. Загальні гейти очікують завершення координованого прогону.

Перші UI-прогони повідомляли при виході 4 ObjectDB instances / 2 resources still in use (негатив портрета — 6/3). Helper тепер очищає посилання на сцени, видаляє SubViewport та аудіо-автолоади і дає mixer 0.1 с до `quit`; виробничий teardown не змінюється. Повторний прогін має перевірити, чи усунено ці повідомлення. Фізичний геймпад, Retina та мобільний safe area не перевірені. Числовий кулдаун лишається джерелом прогресу: заливка іконки знизу вгору за GDD тут ще не реалізована. Повний мобільний контракт читабельності не оголошено виконаним.
