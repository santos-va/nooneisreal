# Матч, повторна гра й ресурси HUD

**Роль:** T2·E Гефест · **Дата:** 2026-10-04 · **План:** [[2026-10-04-Combat-Control]], пряме доручення Santos.

## Звірка

База після оновлення checkout — `65435de`. First-to-two вже задано `GameState.rounds_to_win = 2`; це два раунди при 2:0 або три при 2:1. `MatchRopes` уже володіє скінченним інвентарем і залишками мотузок між раундами. Метод `clear_match()` існував без виклику від справжнього rematch. HUD не очищав піпи перемог і не забирав бойовий ввід для вікна результату.

## Реалізація

`MatchFlow.match_started` відділяє новий матч від наступного раунду. `Arena` очищає існуючий `MatchRopes` лише на цій події. Кнопка REMATCH на результаті скидає рахунок, втому й попередній результат; програмний перезапуск зберігає попередній API. Раунди зберігають мотузки й витрачений інвентар. Жодного нового режиму чи зміни кількості перемог.

HUD синхронізує піпи на початку раунду, показує поточний раунд і ціль перемог, фінальний рахунок, фокусує REMATCH, захоплює й відпускає UI-ввід. Заряди дешу мають кількість і секунди фактичного відпочинку; заповнення залежить від поточної повної тривалості. Нижня підказка бере кнопки меча й стрибка з InputRouter, не дублює клавіатурну розкладку.

## Перевірка

Предмет: для всіх переходів звичайного best-of-three: мотузки й інвентар зберігаються між раундами; rematch очищає їх, рахунок, втому й UI-ввід рівно один раз.

Команда координатора: `godot --headless --path game --script ../tools/match/match_lifecycle_check.gd` — має завершитися `MATCH_LIFECYCLE PASS`; за провалу виправити відповідний перехід та повторити. Негативи `-- --break=round`, `-- --break=rematch`, `-- --break=score` повинні завершитися ненульовим кодом: передчасне очищення, втрачений cleanup, застарілі піпи відповідно.

Позитив і три негативи включено до `tools/gates/playable_check.sh` (`make check-playable`). Негативи дозволяють лише очікувані assertion-помилки з префіксом `MATCH_LIFECYCLE`; помилки парсингу, ресурсів чи інші runtime errors залишаються блокуючими. Runner також підключає нові цільові перевірки керування, анімації, маятника й ульт інших смуг. Синтаксис shell і вкладеного Python перевірено без запуску Godot.

Координатор запустив Godot 4.7 stable послідовно; T2·E прочитав повні результати своєї смуги й підсумок загального запуску:

- `make check-playable` → **40 сценаріїв, 0 провалів**; включений `make check` → **164 smoke-перевірки, 19847 кадрів**, `SMOKE ЗЕЛЕНИЙ`; парсинг — 60 скриптів, 0 помилок.
- Lifecycle → **29 перевірок, 0 провалів**, без warning/error під час завершення. Перший пробний запуск мав витік аудіоресурсів при надто швидкому teardown; очікування завершення аудіопотоків виправило його.
- Негатив `round` → rc=1, один очікуваний провал збереження мотузки/інвентарю. `rematch` → rc=1, два очікувані провали очищення та повернення інвентарю. `score` → rc=1, два очікувані провали очищення піпів. Сторонніх runtime-помилок немає; runner прийняв усі три як успішні негативні контролі.

Локальні свідчення: `/workspace/nooneisreal-env/combat-control/playable-final.log` та `regression-final/match-lifecycle*.log` у тій самій теці; ці зовнішні логи не є переносними артефактами репозиторію, команди вище відтворюють перевірки. Фінальний `make gates` — окремий крок координатора/Феміди; на момент цього запису результат не прочитаний. Візуальний комфорт на Mac цим тестом не доведений.
