# Передача одного меча: стан та ввід

**Дата:** 2026-10-04 · **Виконавець:** T2 A · **Статус:** цільовий sword-state **797/0**, чисте завершення за журналом координатора; фінальна регресія 164/19824 кадри та 32/0 сценаріїв, гейти зелені; native 45/0 у Linux llvmpipe.

## Реалізація

Дія `weapon_swap`: SOLO V, SHARED H/P, геймпад R3. Нові клавіші не замінюють
ультимейт V у SHARED. Підказки InputRouter і ComfortPanel читають актуальну мапу;
чинні UI fences не дозволяють утриманій крізь меню кнопці почати передачу.

Fighter має окремий стан SWAP і physics-лічильник: 24 кадри, одноразова передача
на 12-му (PLACEHOLDER, затверджений T5). Спочатку обробляється переривання вводу,
потім лічильник і контакт. `sword_hand` — єдиний авторитетний власник меча;
`sword_swap_from/to/frame` — дані презентації, `attack_sword_hand` фіксується
на старті кожної атаки. Старі sword-скіли очищають попередній ідентифікатор
кінцівки; лише sword_left_hand_/sword_right_hand_ зберігають normal-chain metadata.
Раунд також викликає API скидання пози меча, щоб презентація не зберігала
попередню передачу. Пауза, hitstop і time freeze не просувають передачу.

Початок дозволено тільки Choko в IDLE/WALK на землі, без зайнятого гарпуна.
Удар ногою та деш переривають і виконуються. Hitstun до контакту залишає стару
руку, після контакту — нову. Решта бойових запитів під час передачі споживаються,
щоб не спрацьовувати після завершення. Невчасна кнопка передачі в атаці чи
зайнятому гарпуні також не зберігається на наступний вільний кадр. Раунд скидає
меч у праву руку; інвентар гарпунів не змінюється.

LimbMoves обирає для озброєної руки `sword_<side>_hand_<variant>`: cut/thrust/rising,
lowcut/aircut. Вільна рука і ноги зберігають limb-прийоми. Числові combat-поля
копіюються з тих самих донорів без зміни шкоди, кадрів, hitbox чи вікна cancel.
Стара virtual-атака й ультимейт також фіксують руку. Меш та анімацію веде окрема
реалізація презентації; її результат не підміняється тестом стану.

`tools/weapon/sword_state_check.gd` перевіряє межі кадрів 11/12/24, справжній
receive_hit, ноги/деш, freeze/pause, заборонені стани, зайнятий гарпун,
останній кадр атаки, відсутність відкладених запитів, V/R3, H/P, UI fences,
утримання без повтору, збереження донорських полів і snapshot руки атаки.
Координатор виконав його: **SWORD_STATE_COMPLETE checks=797 failures=0**, без ERROR (`logs/sword-state2.log`, повторний прогін після narrow-prefix
та reset-pose змін). Дві додаткові перевірки підтверджують очищення попереднього
left_leg перед sword-ультимейтом для обох рук.
`limb_combat_check` тепер очікує sword-презентацію для озброєної правої руки Choko.

Runner реєструє sword-state і sword-presentation як обов'язкові позитивні
сценарії з exit0, sentinel failures0 і без ERROR. `git diff --check` та shell
syntax перевірені локально. Фінальні журнали координатора у
`/workspace/nooneisreal-env/choko-sword/` звірено: `check-playable-final.log` —
**164 бойові перевірки за19824 кадри**, **32 сценарії /0 помилок**; sword-state
повторно **797/0**. `gates-final.log` — зелена батарея, **59 GDS /0 помилок**.
`actual-sword-final.log` — **45 знімків /0 помилок**, тільки попередження VSync.

FPS або живе керування на MacBook Air M3.
