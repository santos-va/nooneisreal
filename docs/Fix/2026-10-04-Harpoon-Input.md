# Два режими гарпуна та ручний look

**Дата:** 2026-10-04 · **Виконавець:** T2 A · **Статус:** повторний запуск підтвердив input177/0, comfort31/0, 164 бойові перевірки та 30 сценаріїв регресії без помилок; гейти зелені, native-прогін координатора11/0 завершився чисто (лише попередження VSync).

## Контракт

План [[2026-10-04-Harpoon-Inventory-Ropes]]. SOLO: Q → `grapple_enemy`, E →
`grapple_parkour`, I → `skill2`. У SHARED на Q/E уже живуть скіли P1: погоджено
P1 T/R та P2 O/I для ворога/паркуру відповідно. Інші клавіші не перенесені.
Старий `grapple` не має фізичних подій; він лишається окремим virtual-маршрутом
для CPU й старих сценаріїв, режим якого явно визначає Fighter.

Геймпад: Y+RT → ворог, Y+LT → паркур. Маршрут фіксується на свіжому натисканні
плеча/тригера й не змінюється при відпусканні Y. Нові дії користуються наявними
UI fences, без прихованого дублювання limb чи legacy grapple.

`look_axis(player)` читає правий стік: радіальна deadzone 0.2, після неї аналоговий
діапазон 0…1; X праворуч, Y донизу. Меню, pause та disconnect блокують залишений
нахил до нейтралі. Наведення у світі й запис ray-on-fire належать окремому helper,
цей код не читає камеру та не пише позицію персонажа.

Панель Comfort показує обидві дії, правила утримання/повернення та запас7/2.
Немає старої підказки «Y+LT reserved». GDD05/06 містять чинну матрицю й пояснення.

## Узгодження руху з ручним оглядом

За уточненням плану ручна камера тепер публікує окремий input-пакет ground-forward.
`DuelFrame.human_to_world` бере його лише на початку людського SOLO-жесту.
Утримана W не змінює напрямок при подальшому повороті камери. InputRouter надає
`view_basis_packet` / `apply_view_basis_packet`: записаний пакет блокує живого
постачальника до виходу з replay. UI/profile/disconnect і `control_locked` скидають
пакет; невірні live-вектори не заміняють останній скінченний напрямок.

`free_movement_check` розширено на90°/180°, рух після нейтралі, replay під різними
фактичними обертами camera node, неправильні вектори та reset-fences. Координатор підтвердив **free-movement54/0** та **aim21/0**, чистий import і
завершення. Окремий pause-edge тест доводить: release і нова W між UI та першим
physics tick беруть новий базис, навіть коли Fighter жодного разу не бачив
нейтраль. Для цього UI/profile/disconnect явно очищають latch у DuelFrame.
Фінальна батарея після цього уточнення також зелена: **164 бойові перевірки
за19824 кадри**, **30 сценаріїв /0 помилок**.

## Перевірка

`tools/input/limb_input_check.gd` розширено реальними keyboard/pad events:
Q/E/I, обидва гравці SHARED, відсутність фізичного legacy аліаса, усі Y-chords,
нейтраль після pause для клавіш/тригерів/модифікатора/look, deadzone та disconnect.
Профілі перевіряються на конфлікти всіх клавіш. Sentinel `LIMB_INPUT_COMPLETE`;
потрібні exit0, failures0 та відсутність ERROR, інакше виправлення й повторний запуск.
Звірено `/workspace/nooneisreal-env/rope-inventory/logs/check-playable-final.log` і
`regression-final/{limb-input,free-movement,harpoon-aim}.log`: **ALL OK164 /19824 кадри**, **30 сценаріїв /0 помилок**,
**LIMB_INPUT_COMPLETE177/0**, **FREE_MOVEMENT_COMPLETE54/0**,
**HARPOON_AIM_COMPLETE21/0**. Pad-тести порівнюють фактичну дію з незалежною
таблицею `[skill1, skill2, grapple_parkour, grapple_enemy]`; помилкова перестановка
LT/RT не може пройти завдяки копіюванню константи реалізації. Нова перевірка
від’єднання доводить, що залишений right-stick нахил не протікає після disconnect.

Smoke більше не зараховує гарпуну історичну регенерацію: перевіряє7/2, незмінний
запас після60с, `available + owned = capacity` та дискретні піпси HUD. Втома від
пострілу збережена. Runner містить нові aim/rope/recovery сценарії зі строгими
sentinel/exit/ERROR вимогами. Godot запускає координатор; цей виконавець
паралельного процесу не запускав.

Фінальне закриття звірено за `logs/gates-final.log` (**БАТАРЕЯ ЗЕЛЕНА**) та
`logs/actual-inventory.log` (**ACTUAL_INVENTORY_COMPLETE shots=11 failures=0**,
rc0 за координатором). Native виконувався на Linux llvmpipe; є лише очікуване
попередження про непідтримуване перемикання VSync. Це не вимірювання FPS
чи слухове приймання на MacBook M3.
