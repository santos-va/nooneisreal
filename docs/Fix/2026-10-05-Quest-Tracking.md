# Вибір доручення й ціль із фактичного прогресу

2026-10-05 · T2 Гефест · progress-смуга [[2026-10-05-District-Journey-Continuity]]. Геометрія, checkpoint-позиції, HUD і орієнтир мають окремих власників; цей документ описує модель та обчислення цілі.

Предмет: явний вибір або вимкнення відстеження належить героєві й переживає reload; ціль відповідає ще не виконаній умові або місцю здачі, ніколи вже завершеному дорученню.

## Аудит і вибір

До зміни `CityProgress.summary()` завжди брав перше active/ready за порядком JSON. Збереження не мало вибраної цілі; читач HUD не міг відрізнити автоматичний вибір від свідомого вимкнення. Контракт усіх шести завдань уже містив достатні goals/events; нова сюжетна система не потрібна.

Варіанти: постійно підміняти перше завдання; зберігати довільну world-координату; зберегти лише дозволений quest id і обчислювати залишок із чинних фактів. Обрано третє. Погляди: новачок зберігає автоматичну ціль; дослідник може вимкнути її; гравець із кількома дорученнями сам вибирає пріоритет; інший герой не успадковує вибір; старий save не втрачає дані; рухомий мешканець не лишає орієнтир на застарілій точці.

## Стан і сумісність

Опціональне поле `heroes[hero_id].tracked_quest` не змінює schema version 1:

| Значення | Поведінка |
|---|---|
| Поле відсутнє | Автоматично перше accepted active/ready; сумісність старих збережень |
| Порожній рядок | Явно вимкнено; зберігається при reload і прийнятті інших завдань |
| Відомий accepted active/ready id | Явний вибір; прийняття іншого завдання його не підміняє |

`track_quest(id)` повертає успіх/відмову; `track_quest("")` вимикає. `tracked_quest_id()` повертає чинний ефективний id або порожній рядок. Завершення явно вибраного завдання прибирає поле й повертає автоматичний вибір наступного; після всіх завершень цілі немає. Явне вимкнення не змінюється від завершення стороннього завдання.

`journal()` додає `tracked`; `summary()` додає `tracked_quest_id` та `tracking_mode` (`auto/off/manual`). Вимкнення має окремий текст вільної прогулянки; фінальний текст усіх шести завершень збережено.

Restore атомарно відхиляє null/число замість рядка, невідомий, неприйнятий, completed або заблокований prerequisites quest id. Під час негативного review також усунуто старе порівняння `version != 1` для неправильних Variant-типів: configure/restore перевіряють точне скінченне число через `_integer`, тому boolean/string/null не створюють SCRIPT ERROR.

## Контракт цілі

`CityQuestTargets.resolve(progress, director = null, origin = Vector3.ZERO)` повертає `{quest_id, id, title, kind, position}` у світових координатах або `{}` при вимкненні/відсутності цілі. Метод лише читає стан; не пише save і не змінює quest/events під час render/physics опитування.

| Доручення | Поки активне | Коли готове |
|---|---|---|
| Знайомства з працівниками | Найближчий ще не зустрінутий працівник, позиція visit його крамниці | Крамниця-замовник |
| Пакунок ниток | Кравець | Крамниця-замовник |
| Верхній маршрут | Ще не відвіданий міст/вежа з CityPlaces | Майстерня |
| Дві опори | Найближча опора CityLayout, якої ще немає в rope events | Майстерня |
| Знайомі обличчя | Ще не зустрінутий перехожий | Кравець |
| Свій колір | Спершу кравець для палітри, потім ще не відвіданий ринок | Кравець |

Для мешканця береться поточний global_position активного актора, потім перетворена у світові координати збережена runtime-позиція, і лише за їх відсутності його стабільний home. Повторна опора/мешканець виключені вже записаними унікальними фактами. Це напрямок на ціль, не навігаційний маршрут крізь стіни.
