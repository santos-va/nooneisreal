# Сюжетний стан і взаємодії службового двору

2026-10-05 · T2 Гефест · [[2026-10-05-Clocktower-Story-Expansion]].

## Звірка та реалізація

Старий `CityProgress` має шість whitelist-доручень, жетони й власний v1 save. Новий `CityStory` не змінює цей формат: окремий `city_story_v1.json` містить лише Choko/Skea, accepted, два whitelist clue IDs, opened/completed та explicit guide selection. Весь документ перевіряється до заміни стану: невалідні типи, duplicate/невідомі факти, неможлива послідовність, координати чи невідомі поля відхиляються. `disk=false` вимикає і читання, і запис. Пошкоджений файл зберігає свої байти навіть якщо поточний епізод пройдено в пам’яті; нормальний запис перевіряє flush/error і атомарно перейменовує temporary file.

[[2026-10-05-Clocktower-Trace]] задає авторський епізод «Слід під годинником». Лада пропонує огляд; explicit acceptance відкриває два справжні факти у довільному порядку; лише після обох можна звільнити важок; відкрита фізична хвіртка зберігається; тільки повернення до Лади завершує главу. Старі доручення не завершуються, їхні жетони не видаються. Невідоме походження поломки залишається невідомим. Репліки героїв читаються тільки перед механізмом, а не після його відкриття.

`CityWorld` читає marker nodes без дублювання geometry coordinates: `clue_a→latch`, `clue_b→counterweight_trace`, `mechanism`. Огляд потребує підтриманого наземного стану, вільних рук, відсутності control/freeze/hitstop/UI lock, близької горизонтальної дистанції й висоти, фактичного mask1 LOS. NPC має пріоритет над предметом; modal inspection забирає UI token і очищає stale input. Story NPC callbacks повторно перевіряють поточного героя, фізичний `can_talk`, сторінку offer та єдиного власника UI. Малий read-only `InputRouter.ui_owned_only_by` не змінює маршрутизацію натискань.

Story state керує тільки наявною геометрією T2 parkour через `set_story_shortcut_open`. Завершення сюжету є джерелом істини: once-only NPC memory відновлюється при reload, якщо незалежний NPC save не встиг записатися. T4 виявив міжфайлову межу: in-memory completion при пошкодженому/невдалому story save не має записувати майбутній факт у NPC save. Тому bond створюється лише коли story saving увімкнений і останній запис успішний; `disk=false` теж не створює durable NPC факт. Це не міжфайлова транзакція: story commit є передумовою, NPC memory можна безпечно відновити пізніше. Local generated flavor не може виконувати команди сюжету.

Одна чинна HUD-картка й один напрям: automatic mode одразу веде до Лади; explicit manual errand/OFF залишаються чинними після acceptance. Кнопка журналу явно обирає сюжет; вибір старого доручення/OFF знімає story selection. Журнал зберігає спостереження й висновок, лишається прокручуваним із keyboard/gamepad focus. Закінчена story button перед приховуванням віддає focus Resume. Верхній title і world guide читають однаковий predicate; старий errand не має другого tracking tick, поки ведеться сюжет.

## Перевірка

Godot **4.7-stable**, тільки ізольовані `/tmp/nir-story-*` XDG dirs. Реальні user saves не читалися й не змінювалися. `tools/world/city_story_check.gd`: **63 checks / 0 failures**, rc0, final raw clean — `/workspace/nooneisreal-evidence/city-story/validation/story-content-final.log`. Покрито строгий restore/контент, skip/duplicate/hero isolation, partial disk resume, corrupted bytes preservation, реальний NPC accept, nested foreign UI lock, guide manual/OFF/explicit story, близький огляд, додаткова фізична стіна, два факти, фактичний механізм, restart walk, return та one-time memory. Додаткові негативи corrupt / filesystem write failure / disk-disabled доводять, що in-memory completed не змінює NPC bond; позитивний complete пише окремий справжній temporary story save. Fixture переносить актора до фізичних точок для тесту interaction boundaries; повний рух маршрутом доводить окремий geometry fixture, ці direct calls не названі natural input walkthrough.

Перший запуск відхилено через HUD `PackedStringArray.push_front` (замінено на `insert`); другий мав missing optional metadata diagnostic на negative LOS (додано `has_meta` перед читанням). Пороги чи негативні assertions не послаблювалися, ранні raw збережено. T4 також виявив Variant boundary у content ID: exact-sized Array/Dictionary замість String давав runtime invalid operands до порівняння. Власний pre-fix запуск це підтвердив (`validation/content-variant-before.log`); додано type guard і два негативи. Ця єдина production поправка після фінального native не змінює валідний JSON або rendering; exact delta/source hashes — `validation/post-native-validator-delta.json`. Native кадри не заявляються byte-identical щодо цього post-capture validator, візуальні файли й контент незмінні.
