# Сліди руху за силуетом видимого героя

**Виконавець:** T2 Гефест. **Дата:** 2026-10-04. **Статус:** реалізація передана на перевірку Godot та аудит T4; результат запуску фіксує головний термінал.

Предмет: для всіх скелетних знімків Skea та Choko привид повторює видимий mesh,
Skin, позу й світовий масштаб у момент знімка та надалі не залежить від руху героя.

## Причина та зміна

`Afterimage.spawn()` раніше отримував `RigAnimator.part_snapshot()` і будував
капсули, хоча `SkeletalRig` показує Meshy-героя з іншими пропорціями. Відмінність
силуету та розміру була наслідком іншого джерела геометрії.

`Afterimage.snapshot(animator, skeletal)` зберігає світові трансформи mesh і
Skeleton3D, поточні локальні position/rotation/scale кісток без реконструкції через глобальну матрицю,
rest, enabled, show_rest_only, blend shapes та посилання на mesh/Skin.
Привид створює лише незалежний Skeleton3D та MeshInstance3D зі спільними незмінними
ресурсами. Повна сцена, AnimationPlayer, фізичні вузли та масиви вершин не копіюються.
Матеріал привида — один власний `FxShader.stroke` без додаткового outline pass;
тіні вимкнено. Геометрія та skinning лишаються геометрією видимого героя.

Заміни у `Fighter.gd` і `GrimoireFx.gd` стосуються лише аргумента знімка.
Кадри, переходи станів, hitbox, physics, колір, lifetime, alpha, offset і drift
залишаються тими самими. Попередній API `spawn(parent, Array, ...)` приймає старий
capsule snapshot; без скелета новий helper також повертає капсули.

## Трансформи й бюджет

Привид має `top_level`, тому довільний трансформ FX-батька не масштабує вже світові
координати вдруге. До mesh та Skeleton3D застосовується одна афінна операція:
`p' = center + scale_mult × (p − center) + offset`. Центр — поточний центр тазової
капсули, як у попереднього ефекту. Це зберігає імпортований масштаб арматури,
поворот героя і навмисні збільшення гримуара ×1.3 та ×1.36.

`Fx.enabled = false` блокує і захоплення, і spawn. На дерево — максимум 16 привидів;
наступні пропускаються до алокації mesh/skeleton/material. Це обмеження презентації,
не число бою. Після завершення lifetime звільняється дерево привида; спільні ресурси
залишаються у героя. Знімок не містить посилань на живі Node героя.

## Перевірка

Команда з кореня репозиторію:

```bash
"$GODOT_BIN" --headless --path game -s "$PWD/tools/fx/afterimage_check.gd"
```

Умова проходження — 0 failures та rc=0. Тест завантажує обох справжніх героїв,
встановлює dash pose, перевіряє спільні mesh/Skin, кожну кістку та вибірку skinned
вершин зі справжнього mesh. Випробовує ×1/×1.3/×1.36, зміщений/повернутий/нерівномірно
масштабований FX-батько, незалежність після зміни пози героя, завершення життя,
capsule fallback, вимкнення FX і стелю кількості. При провалі — не оголошувати
ефект готовим; відокремити transform/pose/resource/lifecycle причину й повторити тест.

Нативна перевірка зображення (без `--headless`, потрібен робочий DISPLAY):

```bash
"$GODOT_BIN" --path game --rendering-method gl_compatibility --resolution 1152x648 \
  -s "$PWD/tools/fx/afterimage_check.gd" -- \
  --capture-dir=/workspace/nooneisreal-env/playable/render/afterimage
```

Додатковий режим зберігає 8 PNG: для кожного героя `pair` (герой ліворуч,
привид праворуч), `overlay` (точно спільне місце), `hero` і `ghost` з тим самим
ракурсом. Це справжній GLB, dash pose, матеріал героя та матеріал ефекту; жодна
анімація або фізика під час захоплення не просувається. Статус зображень до запуску
головним терміналом — не перевірено.

Незалежні форми дефекту, які ловить перевірка: інший mesh при правильному розмірі;
живий skeleton при правильному першому кадрі; подвійний батьківський масштаб або
втрачений масштаб імпорту. Піксельне зіставлення та `make check` / `make gates` —
у головного термінала. Продуктивність на M3 8 GB і телефоні тут не вимірювалась.
