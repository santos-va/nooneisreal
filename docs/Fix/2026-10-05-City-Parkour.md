# Міські уступи та обмежені стінні кроки

**Дата:** 2026-10-05 · **Роль:** T2 Гефест · **Статус:** локальна механіка перевірена Godot 4.7; native огляд завершено в окремому аудиті; загальна інтеграція триває.

Предмет: для всіх міських захоплень і підйомів: реальна капсула проходить лише вільним маршрутом до перевіреної опори, а повітряне зусилля має скінченний бюджет.

План [[2026-10-05-Responsive-Parkour]] звірено з CityFighter/Fighter, капсулою 0,35 × 1,8 та геометрією CityLayout/CityDistrict. До зміни CityFighter не мав уступів або стінного руху. Нова city-only підсистема не вводить станів у duel Fighter. Профіль `game/data/world/city_parkour.tres` та його exported поля позначено PLACEHOLDER; це не фінальний баланс.

Під час стрибка утримання jump і напрямок у стіну дозволяють захоплення обом героям. Для підйому треба відпустити й повторно натиснути jump. Block, crouch або grapple_detach відпускають; dodge може перервати. Висіння обмежене часом; `hold_remaining` дозволяє HUD показати залишок. Висота кистей над root — 1,42 м PLACEHOLDER після перевірки фактичної довжини рук анімаційною смугою; фізичний зазор капсули до стіни збережений. Skea має одну коротку серію стінних кроків до нового контакту з підлогою. Відпускання jump або напрямку завершує її. Рух не починається під час grapple/recovery; зміна стану, блокування керування, reset або motion_revision скидає presentation.

Фізичні перевірки: вертикальна стіна, горизонтальна верхня поверхня, дві точки кистей, підлога під landing, capsule sweep для обох сегментів mantle та endpoint overlap. Рухомі/видалені опори відпускають героя. Повторне захоплення після падіння заборонене до опори. Анімаційний контракт — `parkour_presentation`: phase, progress, дві кисті, wall_normal, wall_point, direction, speed. Швидкість читається з фактичного зміщення за tick.

У світі додано навчальний уступ біля spawn: центр `(4; 1,4; 29)`, верх `2,8`. Короткий маршрут до наявного північно-східного даху: `(12; 2; -5,8)` → `(12; 4; -8,6)` → дах `y=4, z<-10`. Широкі кам’яні опори мають видимий латунний край, без нових зовнішніх assets. Шлях центром вулиці й східна рампа збережені.

Native preview виявив реальну невідповідність: видимі пілястри й кам’яні пояси виступали перед основною стіною, але не мали collision. За погодженням координатора `CityArchitecture` тепер створює collider точного розміру для пілястр, поясів, карнизів, кам’яних віконних рам/арок/підвіконь і віконниць. Невидима загальна оболонка не додається. Нова фізична регресія перевіряє фактичний пілястр східного крила `(x=14,z≈30,2)`, зовнішнє положення капсули та обмеження повторного зусилля. Фінальний native огляд і наступне виправлення всього shoe footprint задокументовано у [[2026-10-05-Parkour-Visual-Audit]]: 210 PNG / 420 ticks у прийнятому локальному наборі. T2 звірив sentinels повторів wall-fixed47, wall-opposed-fixed47, ledge-fixed47 та shoe-clean; вони завершені з 0 failures. Приймання Mac/M3 та апаратного FPS цими записами не заявляється.

## Перевірки

Команда: новий `tools/parkour/city_parkour_check.gd` через Godot; умова — завершений sentinel, 0 failures, чистий raw log. На провалі — виправлення мотору/fixture, без оголошення готовності. Негативні форми: дах над головою, вузька/недостатня landing, зникла/переміщена опора, повторний wall-run без підлоги. Координатор виконує загальні make check/gates/playable після інтеграції.

Реальний запуск офіційного `Godot_v4.7-stable_linux.x86_64`: **69 checks / 0 failures**, чистий raw log `/workspace/nooneisreal-evidence/parkour/mechanics/city-parkour47-final.log`. Охоплено обох героїв, негативні геометрії, timeout/hold_remaining, InputRouter → shipped practice ledge → mantle та реальний виступ пілястри. Імпорт 4.7 чистий у `import47-network.log`; перший sandbox-only import мав помилки локального socket і не зараховується. Спроба `city_runtime_check.gd` після цього впіймала одночасну анімаційну правку `SwordPresentation.gd:221` (не виводився тип busy); її зупинено, передано власнику, цей журнал не є runtime-прийманням.

Після додавання чотирьох реальних input-перевірок обох сходинок до даху загальна батарея виконала **73 / 0**, але відхилила teardown: 14 ObjectDB instances / 4 resources ще існували під час exit (`responsive-parkour/validation/playable/city-parkour.log`). Цей запуск не є зеленим прийманням. Fixture звільняв audio singletons і завершувався через один process frame; під `--fixed-fps 60` це не дає mixer реального часу на завершення Ogg playback. Додано наявний у physics-motion/native-capture патерн: 250 мс wall-time drain після звичайного teardown. Production audio й попередження не вимикаються; початковий журнал збережено. Повтор на офіційному Godot 4.7 із `--fixed-fps 60 --verbose` завершився **73 / 0, rc0**; у повному журналі `parkour/mechanics/city-parkour47-teardown.log` немає ERROR/WARNING, ObjectDB/resource leaks або orphan записів. Це приймання виправленого fixture; загальну батарею координатор повторить окремо.
