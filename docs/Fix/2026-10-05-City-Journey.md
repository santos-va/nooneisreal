# Безпечне продовження міської подорожі

2026-10-05 · T2 Гефест · реалізація [[2026-10-05-District-Journey-Continuity]].

## Аудит і вибір

Початковий `CityWorld._ready()` завжди відновлював героя біля входу, хоча NPC, доручення та кольори вже зберігалися. Звірено фактичні `CityPlaces`, геометрію інтер'єрів і `CityFighter.restart_at()`. Варіанти та погляди гравця, другого героя, новачка, дослідника, користувача геймпада і пошкодженого save описані в плані: обрано іменовані безпечні місця замість довільного фізичного snapshot.

## Реалізація

`CityJourney` зберігає окремий `user://city_journey_v1.json`: `{ "version": 1, "heroes": { "choko": "grocer", "skea": "roof_bridge" } }`. Відомі лише Choko/Skea і сім дозволених ідентифікаторів; координати, камера, посилання на ресурси, запас/стан мотузок і бойова поза у файл не потрапляють. Шість місць беруться з `CityPlaces`, вхід — з `CityLayout`.

| ID | Безпечна точка, метри | Поверхня |
|---|---|---|
| spawn | (0, 0, 23) | вхід до кварталу |
| clock_tower | (-24, 4, -19) | дах перед вежею |
| roof_bridge | (0, 4, -20) | міст дахів |
| market_court | (0, 0, 20) | ринкова площа |
| grocer | (-26.6, 0, 15.4) | вільний прохід крамниці |
| tailor | (-20, 0, 15.4) | вільний прохід ательє |
| workshop | (-13.4, 0, 15.4) | вільний прохід майстерні |

Активація потребує 0,5 с неперервного перебування в радіусі 1,6 м, різниці висот не більше 0,25 м, справжньої підтримки `is_on_floor()`, малої вертикальної швидкості та стану IDLE/WALK/CROUCH/BLOCK. Політ, тримання мотузки, постріл і змотування не активують точку. Прохід під мостом не активує дах. Пороги — відкриті `@export` PLACEHOLDER для комфорту дослідження; бойові числа не змінені. Незмінна точка не спричиняє повторного запису щокадру.

Завантаження приймає тільки повністю валідний документ до 4096 байтів. Схема, тип версії, перелік героїв і whitelist перевіряються до зміни стану: частково валідний документ не може перезаписати одного героя. Невідомі додаткові поля, довільні координати, bool/string/fraction замість версії та невідомі місця відхиляються. Пошкоджений файл залишається байт-у-байт незмінним; збереження цього сеансу вимикається, герой безпечно починає біля входу. Без файла старий профіль продовжує працювати; дані доручень та NPC не мігруються і не переписуються.

Запис виконується у сусідній `.tmp`, перевіряє flush/error і атомарно перейменовується поверх чинного файла. Це атомарна заміна файла, без заяви про гарантію проти фізичного знеструмлення диска. `save_ok` окремо передано HUD: помилка checkpoint-save не маскується успіхом збереження доручень.

CityWorld відновлює валідну точку через наявний `restart_at()`, що очищує швидкість, бойовий стан і мотузку. Падіння за межі району повертає до останнього безпечного місця; **«Почати прогулянку знову»** явно скидає checkpoint лише поточного героя до входу. Камера починає зі звичайного напрямку; точне відновлення камери не обіцяється. Попередній duel/water/input-контекст після виходу відновлюється як раніше.

## Перевірка

Предмет: для всіх дозволених героїв і checkpoint-ів відновлена позиція має підтримку, вільну капсулу та не походить із довільних координат save.

`tools/world/city_journey_check.gd` перевіряє реальні сцени і фізику обох героїв: усі сім місць, фактичну `BodyShape` героя, відсутність бокової корекції колізії, dwell, короткий візит, політ, мотузку, змотування, неправильну висоту під дахом, повторний вхід у крамницю/на міст, очищення runtime-руху, відновлення після падіння, явний restart та ізоляцію профілів. Негативні контролі охоплюють три різні класи: зіпсований синтаксис/розмір, некоректний тип/схему, невідомі імена/довільні координати. Відкинутий restore не змінює попередній валідний стан; пошкоджені байти лишаються після спроби restart/save.

Локальний Godot 4.7 headless повтор: **122 перевірки / 0 помилок**, без runtime/resource-помилок. Усі 14 комбінацій герой × точка мають фактичну висоту поверхні +0,00082 м і вільну повну `BodyShape`; журнал `/workspace/nooneisreal-evidence/district-journey-continuity/journey-check.log`. Перевірка ізольована від checkout і реальних save. Незалежне native-приймання та загальні gates фіксуються окремо в [[2026-10-05-District-Journey-Review]] і [[2026-10-05-District-Journey-Session]].

`playable_check.sh` зберігає всі 57 попередніх сценаріїв і додає journey/tracking/journal — разом 60. Кожен сценарій має власний профіль: Linux використовує тимчасовий `XDG_DATA_HOME`; macOS — унікальний тимчасовий каталог у системному Application Support і тимчасове дзеркало проєкту з Godot `config/use_custom_user_dir` / `config/custom_user_dir_name`. `HOME` не змінюється, оригінальні save не копіюються. Реальний Linux/Godot probe примусово перевірив custom-directory гілку: `OS.get_user_data_dir()` збігся з виділеним каталогом, файл з’явився тільки там, після завершення дзеркало й профіль видалені. Це перевірка механізму Godot, **не нативне macOS-приймання**.
