# Процедурна вода — об'єм і мальовані гребені

2026-10-04, T2 Гефест, смуга WATER. Пряма згода Santos на процедурні зміни гри передана Дедалом; 0 платних викликів, 0 нових ассетів.

## Звірка та вибір

Перевірено `Water.gd`, `WaveField.gd`, `river_water.tres`, шейдер, [[Stage-River]], конституцію, роль T2 і зовнішній аудит `/workspace/nooneisreal-env/audit/t6/report.md`.
Вода вже має один густий PlaneMesh з трьома хвилями та валом. Нова поверхня не потрібна: бракувало нормалей нахиленої води, а стрибкоподібний hash відблисків створював мерехтіння.

Варіанти: A — лише заміна кольорів; B — той самий displacement, аналітичні нормалі, контури та рухомі процедурні мазки піни; C — додаткові шари, рефракція й відбиття. Вибрано B: об'єм походить від наявної геометрії, без прозорого перекриття й екранних буферів.

Погляди: новачок бачить напрям і гребені хвиль; досвідчений гравець має зберегти видимість ніг; малий екран потребує великих кольорових плям; орбітальна камера не повинна отримувати дзеркальний блиск; replay-перевіряльник має бачити незмінний стан бою; дальній спостерігач — плавний стик із мальованим фоном. Це мірила приймання, не вже підтверджений художній результат.

## Реалізація

`water_toon.gdshader` обчислює висоту й аналітичний градієнт тієї самої функції, яку використовує WaveField, включно з напрямами XZ та валом. Вершини одержують нормалі; фрагмент використовує інтерпольований градієнт для пласких кольорових зон нахилу. Кремова піна й графітовий контур розриваються безперервною процедурною маскою; усі рухи йдуть від чинного `wave_time`. Порогові контури згладжуються через `fwidth`. Немає TIME, читання depth/screen, texture fetch, додаткових mesh чи проходів; матеріал лишається непрозорим unshaded. Частота та кількість існуючих вершин збережені.

`WaveField`, `river_water.tres`, бойові числа, кільця тримання та порядок physics tick не змінено. Збережено чинну поведінку паузи/зупинки часу; окреме нове правило заморожування води не додавалося. API для бризок — існуючі `height(x,z)`, `gradient(x,z)`, `time_s()`.

## Перевірка та межі

Предмет: для всіх чинних параметрів WaveField висота та градієнт шейдера використовують ту саму суму трьох синусів і валу, а оздоблення не змінює стан бою.

Статично звірено формули, відсутність TIME/нових ресурсів, додатні довжини хвиль у `river_water.tres`. Геометрія не збільшена; у vertex додано чотири cosine та арифметику градієнта. Це опис вартості, не вимір FPS.

Зовнішня команда `python /workspace/nooneisreal-env/playable/water/check_surface.py` пройшла: 120 числових проб для площинного/XZ режимів, різних часів і трьох рівнів валу; аналітичний градієнт проти центральної різниці має максимальну похибку 9.29e−11. Чинні uniforms скінченні, wavelength > 0, похідна Z у площині = 0. Це CPU-перевірка формули, не виконання GPU-шейдера. `git diff --check` також пройшов.

Godot не запускався у смузі WATER: Дедал серіалізує рушій для спільної гілки. Необхідні перевірки: `make check` → smoke без помилок; `make gates` → зелена батарея; реальний GL Compatibility render → без shader compile errors. На провалі шейдера — виправити до приймання, а не називати headless-імпорт доказом рендеру.

Приймальні кадри: river DAY/NIGHT, free/plane, одна камера й кадри 0/60/120, окремо пік валу. Перевірити об'єм гребенів, видимі ноги/кільця/бризки, відсутність стрибків піни, плавний дальній стик. Повторний кадр з незмінним `field.frame` має збігатися; порівняти replay guard до/після. Числовий GPU-бюджет і мобільний вигляд ще не виміряні.
