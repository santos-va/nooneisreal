# Наведення гарпуна й ручна камера

T2 Гефест, 2026-10-04. Реалізація за погодженим [[Plans/2026-10-04-Harpoon-Inventory-Ropes]]. Перевірки рушієм виконує T1 послідовно. Фінальний запуск — **21 перевірка, 0 помилок**, включно з базисом руху та фактичними кнопками HUD; журнал чистий. Повторне використання input-event виправлено окремим об’єктом release.

## Контракт і межі

`HarpoonAim.capture` фіксує світові origin/point/direction, режим, гравця, tick та стабільний шлях цілі. `GrappleHook.fire` приймає також записаний словник для відтворення без читання камери. Підказка не означає влучання: авторитетним лишається swept-контакт наконечника. Рука до точки перевіряється на перекриття; камера не гарантує пострілу з-за стіни.

Автоматично вибирається найближча придатна видима ціль у напрямку руху/тіла; рівність вирішує шлях вузла, гістерезис утримує лише ще придатну ціль. Ручне наведення бере промінь середини viewport, шукає кандидатів біля нього й переводить кінцеву точку до руки. Це локальні scene-path ID, не готовий протокол мережевих ID. Нові вороги беруться з групи `fighters`, точки з `grapple_anchor` та `deployed_rope`.

RMB + рух миші або правий стік керують orbit у solo. Автоматика не перебиває ручний напрямок, потім плавно повертається. Спільна камера лишається симетричною: окреме ручне наведення двох гравців — наступний UX-зріз. UI блокує рух камери, затиснений через UI RMB вимагає нового натискання. Render-підказка не змінює історію вибору пострілу. Round reset очищає ручний стан і попередній вибір через HUD. У сценах без HUD власник раунду має викликати `reset` сам.

Під час ручної камери та повернення helper публікує горизонтальний напрямок погляду як окремий input-пакет у `InputRouter`. Новий жест руху бере цей базис один раз; утриманий жест не перекручується разом із камерою. Replay інжектує записаний пакет, а Fighter не читає Camera3D. UI/reset/автоматичний режим очищають живий пакет. HUD бере назви Q/E або T/R та геймпадні акорди з чинної input-мапи, не з констант.

Усі нові числові пороги допомоги/чутливості/затримки — **PLACEHOLDER**, `@export` у helper. Ні комфорт на M3, ні точність Retina цим ще не підтверджені.

## Перевірка

Предмет: для придатних кандидатів вибір стабільний і не утримує закриту або недосяжну ціль; UI та спільна камера не отримують ручного solo orbit.

Команда: Godot 4.7 `--headless --path game --script ../tools/aim/harpoon_aim_check.gd`. Умова: sentinel `HARPOON_AIM_COMPLETE`, failures=0, без SCRIPT ERROR. При провалі — виправлення коду/сценарію та повтор перед загальними гейтами. Контролі: перестановка порядку групи, нова перешкода після вибору, винесення за дальність, UI під час затиснутого RMB, режим спільної камери. Native-запуск T1 з реальними подіями вводу завершився `ACTUAL_INVENTORY_COMPLETE shots=11 failures=0`; T1 переглянув ручну камеру й мітки. Це Linux llvmpipe, не вимір M3.

Фінальні артефакти в `/workspace/nooneisreal-env/rope-inventory/`:

- `regression-final/harpoon-aim.log` — `HARPOON_AIM_COMPLETE checks=21 failures=0`.
- `logs/check-playable-final.log` — 30 сценаріїв, 0 невдач.
- `logs/actual-inventory.log` — 11 native-кадрів, 0 невдач; лише відоме попередження драйвера про V-Sync.
- `logs/gates-final.log` — фінальні гейти пройдено.

Залишкове дрібне UI-обмеження аудиту: проєктована точка прицілу перевіряється на входження в екран, але довгий геймпадний підпис біля краю не затискається повним прямокутником. Після фінального тесту код не змінювався.
