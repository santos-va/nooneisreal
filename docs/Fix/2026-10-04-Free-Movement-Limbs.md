# Вільний жест руху та нормалі чотирма кінцівками

**Дата:** 2026-10-04 · **Виконавець:** T2 A Гефест · **Статус:** реалізовано, бойові й цільові перевірки пройдені; фінальні гейти та візуальне приймання координатора очікуються.

## Причина і рішення

`DuelFrame.to_world` для SOLO використовував підписану лінію P1→P2. Після проходу крізь суперника вона розвертала утримувану W; `_walk_free` також проєктував бічний крок назад на коло навколо цілі. План [[Plans/2026-10-04-Free-Movement-Limbs]] замінив саме людський шлях вводу: початок жесту запам’ятовує неперервний базис симуляції, нейтраль його звільняє. Позиція чи обхід ворога не згинають уже утримуваний напрямок. Камера не передає свої render-трансформи в симуляцію.

Людина рухається прямо і дивиться вздовж руху; початок нової атаки явно обирає поточного суперника. Під час продовження комбінації залишається наявний обмежений tracking. CPU зберігає старі тактичні напрямки й обхід. Площинний режим не змінено. Майбутній вибір між кількома цілями не реалізований цим зрізом.

`LimbMoves` створює окремі ресурси пози з наявних light/heavy/crouch_light/air_light. Усі бойові числа донора збережені; відмінні права/ліва кінцівки та контекстні пози не обіцяють окремих зон шкоди. Normal-string обмежений трьома діями; нога завершує його, включно з нижньою ногою на донорі tier0. Нове продовження дозволяє лише підтверджене влучання: приріст `stats.hits` після `receive_hit`, а не `has_hit`, який означає також блок чи неуразливість. Legacy virtual light/heavy і пріоритет skill/ultimate збережені.

## Перевірка

Предмет: для всіх людських жестів напрямок не залежить від руху цілі до нейтралі; для всіх нових limb-варіантів бойові поля відповідають донору, а normal-string не перевищує трьох підтверджених ударів.

- `tools/input/free_movement_check.gd`: реальні W/D, перетин цілі, її обхід під утриманою W, новий жест після нейтралі, розворот тіла, фактичний деш після перетину, CPU, прямий бічний рух та площина. Координатор підтвердив **26 перевірок, 0 помилок**, чисте завершення. Негативні форми `--break=opponent_frame`, `orbit`, `facing` завершилися очікуваним rc=1 зі своїми scoped assertions; runner зарахував усі три.
- `tools/input/limb_combat_check.gd`: повна інваріантність бойових полів донора для обох героїв, dispatch кінцівки, межа комбінації, переривання та справжні hurtbox-query для hit/block/invulnerability/whiff. Перший прогін викрив помилку стенда: без підлоги `on_ground` справедливо повертав false, тому друга атака отримувала повітряний донор. Стенд виправлено через пласку production-поверхню WaveField та очищення залишкових відхилених input buffers між незалежними випадками; повторний запуск координатора: **2950 перевірок, 0 помилок**, чисте завершення.
- `SmokeTest` зберігає старі virtual-сценарії як CPU-наміри після завантаження арени. Реальні клавіатурні сценарії явно повертають людський режим. Це не підміна нової поведінки: нові людські контракти мають окремий production-тест реальними подіями.

Звірено журнали координатора `/workspace/nooneisreal-env/free-limbs/logs/check.log` та `regression-only.log`: `make check` — **164 перевірки, 19839 кадрів, SMOKE ЗЕЛЕНИЙ**; окрема сувора playable-батарея — **27 сценаріїв, 0 помилок**. Початкові падіння smoke на старих припущеннях про миттєвий гарпун/формат підказки виправлено зі збереженням перевірок нового контракту. Фінальні `make gates`, native-приймання та перевірку macOS цей документ ще не оголошує завершеними. Godot запускає лише координатор послідовно; цей виконавець не запускав паралельний процес.
