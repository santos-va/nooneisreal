# Бойові анімації: завершення удару й повернення до руху

Дата: 2026-10-05. Виконавець: T2 Гефест, окрема смуга координатора.

Предмет: для всіх переходів із удару до стійки, ходьби та присідання візуальна поза повертається без миттєвого перескоку; новий удар, реакція на влучання й ривок негайно перебирають позу. Презентація не змінює шкоду, frame data, колізії чи переміщення бійця.

## Аудит і вибір

`SkeletalRig._physics_process()` уже відтворює авторські UAL-кліпи за кадрами бійця; `ProceduralMotionFallback` переносить чотири кінцівки й спеціальні пози з капсул. Після ATTACK→IDLE/WALK/CROUCH старий код одразу робив `seek()` іншого кліпу. Кістки без постійного треку могли зберігати процедурну позу. У `RigAnimator._is_step()` останній кадр recovery не був обов'язковим малюнком.

Розглянуто три варіанти: збільшити загальне згладжування (затримало б удари), увімкнути довільні blend-переходи AnimationPlayer (не контролює наш ручний seek і процедурний шар), обмежити повернення лише виходом із удару. Обрано третій варіант.

П'ять поглядів: новачкові потрібна видима готовність після удару; гравцеві комбо — точний наступний контакт; гравцеві, що відходить, — рух без блокування; противникові — миттєва реакція на шкоду; повтору/симуляції — незмінні hitbox і кадри. Новий шар задовольняє ці межі, художній комфорт потребує живого огляду.

## Зміни

- Окреме повернення скелета протягом експортованого `attack_return_seconds` (PLACEHOLDER 0,10 с). Вихідна поза зберігається, ціль продовжує рухатись із поточним кліпом. Hitstop і time stop заморожують також годинник переходу.
- Будь-яка нова атака, реакція, ривок або спеціальний рух скасовує шар. Ragdoll, левітація й відновлення мотузки не перехоплюються.
- Перед наступним seek відновлюється базова поза шару, щоб пропущені постійні треки не накопичували зміщень. Після виходу з procedural fallback кістки повертаються до rest перед авторським кліпом.
- Останній recovery-кадр завжди оновлює процедурний малюнок, навіть між 12-fps кроками.
- Використано вже наявні UAL/процедурні рухи; нових завантажених чи платних ассетів немає. Базові Sword/Kick/Melee_Knee уже мають mapping і контакт у character `.tres`; довільні кліпи не призначалися чотирьом кінцівкам без вимірювання сторони/контакту.

## Перевірка

`tools/animation/combat_presentation_check.gd` розширено для обох персонажів: останній recovery-малюнок, три цільові стани, неперервність першого кадру, незмінність combat authority, завершення шару, заморозка. Три форми негативного контролю — нова атака, HITSTUN, DASH під час незавершеного повернення: шар має зникнути негайно.

Ізольована копія `/tmp/nir-combat-check`, Godot **4.7 stable**: `combat_presentation_check.gd` — **167 перевірок / 0 помилок**, включно з procedural та authored атаками обох персонажів; журнал `/tmp/nir-combat-presentation47.log`. Додатково тією ж версією: character motion **860/0**, idle presence **18120/0**, foot contact **774/0**, sword presentation **228/0**, combat identity **5366/0**. Журнали `/tmp/nir-combat-*47.log`. `git diff --check` для змінених файлів — без помилок.

Старий idle presence guard порівнював ATTACK→WALK із raw seek у першому кадрі, коли новий шар навмисно активний. Тест тепер обмежено чекає його завершення, перевіряє очищення source/base, а тоді виконує незмінні порівняння raw seek і незалежного fresh mannequin. Ранню неперервність окремо доводить combat presentation.

Загальні `make check` / `make gates` виконує координатор після інтеграції. Native Mac/M3 та художня якість не перевірені; headless-перевірки доводять переходи й незмінність authority, а не остаточний вигляд.
