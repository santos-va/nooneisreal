## Клавіатура SHARED — двоє на одному Mac

## Вільний рух (0.3) — лише за `GameState.free_move`

Рішення — [[ADR-014-Free-Movement-Layout]] (**прийнято** 2026-10-03). Перемикач режиму — [[06-UI-UX]] § Кнопка «РЕЖИМ 2.5D / 3D». План — [[2026-10-03-Prototype-0.3-Free-Movement]] § 0.3-C.
Правила руху, швидкості й деш — [[02-Combat-System]] § Вільний 3D-рух (Арес). У режимі площини діють таблиці вище
без змін. Нових імен дій немає: `p*_up` / `p*_down` уже є в `InputRouter.ACTIONS`.

**Ввід відносно камери дуелі.** `InputRouter.move(player) -> Vector2`: x — праворуч на екрані, y — вглиб кадру.
Камера одна на двох. Базис беремо з фізичного такту `DuelCamera` (після клампу 3°/тік), а не з рендера. Під Flash Step
і 6 кадрів після нього базис замкнений. Камера перпендикулярна до лінії бійців, тож **A/D (←/→) — до суперника чи від
нього**, **W/S (↑/↓) — обхід по колу**, діагональ — і те, і те.

(`InputMap.action_get_deadzone("p1_up")` у Godot 4.7.2 headless → 0.2). Godot 4.7.2 масштабує силу за порогом:
стік 10° → `move()` (0.98, 0) — y під порогом; 45° → (0.58, 0.63), кут 47.5°. Для руху в 360° потрібна одна радіальна
мертва зона замість трьох осьових. Число — **PLACEHOLDER**, бриф Архімеду.

### Деш (ухил) у 8 напрямках — запуск 10

Правило — Арес, [[02-Combat-System]] § Вільний 3D-рух, рядок «деш»: напрям стіка відносно камери, 8 напрямків; бекдеш
Choko з 6 i-кадрами — лише від суперника; деш убік — без i-кадрів. Ця таблиця — як його натиснути на кожному пристрої.
**Нових дій немає**: `p*_dash` + `InputRouter.move()`; ADR не потрібен. Деш без напрямку — вперед, до суперника
(`Fighter._aim_dash`).

| пристрій | деш | напрям | клавіш / пальців разом | примітка |
|---|---|---|---|---|
| клавіатура SOLO, P1 | LShift (тримати або тиснути) | W A S D, діагональ — дві | ≤ 3 (LShift + 2) | RShift вільний |
| клавіатура SHARED, P1 | C | W A S D | ≤ 3 | — |
| клавіатура SHARED, P2 | `.` | ← ↑ → ↓ | ≤ 3 | `.` поруч із `,` (ульта) — один ряд |
| геймпад Xbox / PS | B / ○ | лівий стік | 2 пальці | D-pad дає лише ← / →: ↓ — присід, ↑ — ульта (ADR-014 п. 4) |
| тач (фаза 4) | кнопка **ДЕШ** 56 dp у кластері правої руки | віртуальний джойстик зліва | 2 пальці | флік джойстика — опція в налаштуваннях, за замовчуванням вимкнено |

Екран ≠ суперник. Напрям береться **відносно камери**; що з них «від суперника» (і чи дає i-кадри), залежить від
режиму камери: соло проти CPU камера за P1 ([[ADR-015-Solo-Camera-Behind-Fighter]]) — S / ↓ / стік ↓ = від суперника;
VERSUS збоку — A / ← = від суперника для лівого бійця. Підказка це каже ([[06-UI-UX]] § Підказка дешу).

**Чому тач — кнопка, а не флік (рішення T8).** Один мувсет — одна модель на всіх пристроях: «деш + напрям», як на
клавіатурі й геймпаді. Флік конфліктує з ходьбою: гравець уже тримає джойстик ↑ і хоче деш ↑ — флік вимагає відпустити
й смикнути знову. Ціна — шоста кнопка в кластері нижче 30 % висоти ([[06-UI-UX]] § Смуга бійців); чи вміщається на
390 pt (30 % = 117 pt, дві смуги 56 + 8 dp = 128 dp) — **не перевірено**, макета тач-лейауту немає. Якщо не влазить —
деш іде в другу дугу вище, а не в флік.

**Перевірка — 0 конфліктів і всі 8 напрямків** (Godot 4.7.2 headless, сесія 2026-10-03):

```
$GODOT_BIN --headless --path game -s $PWD/tools/input/dash8_check.gd
```

→ SOLO 14 клавіш-подій, 0 конфліктів, P1 8/8; SHARED 28, 0 конфліктів, P1 8/8, P2 8/8; геймпад P1 8/8, P2 8/8;
`dash8: OK (0 помилок)`, rc=0. Скрипт тисне справжні події в справжній `InputMap` гри після
`InputRouter.apply_profile` з `free_move = true`, тож LShift + W перевірено на рівні Godot, не таблицею. Тач у грі ще
немає — не перевіряється.

**Знайдено (не перевірено на залізі):**

1. **Стік не 8 напрямків, а будь-який кут.** `_aim_dash` бере `_wish.normalized()` — аналог. Клавіатура дає лише
   8 кутів, тож геймпад має ухили, яких клавіатура не має, і навпаки ширші «осьові смуги»: x тримається до ±11° від
   осі, y — до ±17° (пороги 0.2 / 0.3 вище). Нечесно між пристроями.
2. **Діагональ скошена:** стік 45° → деш під 47.5°, бо пороги ↑↓ і ←→ різні.
3. **Windows: LShift × 5 поспіль відкриває діалог «Залипання клавіш»** (Sticky Keys) — відома поведінка Windows, тут не
   перевірено; деш у SOLO — саме LShift, а 5 дешів поспіль у бою реальні. Бриф Архімеду: джерело (URL Microsoft) і чи
   гасить це щось, крім налаштувань користувача. До відповіді — рядок у підказці налаштувань Windows-збірки.
4. Діагональ «назад + вбік» (135° від суперника) у коді **дає** i-кадри: `_aim_dash` рахує «назад» за
   `dot(forward) < −0.5`, тобто > 120°, а ADR-014 п. 5 — > 135°. Що з діагоналлю — питання Аресу.

**ТЗ Гефесту (T2·A, власник `Fighter.gd`; `InputRouter.gd` — теж код Гефеста):**

1. `InputRouter.dash_dir8(player) -> Vector2i` — `move(player)` → `snapped(angle, 45°)` → один із 8 одиничних
   векторів (екранних); нуль, якщо `move().length()` < порогу. `Fighter._aim_dash` / `_aim_flash` беруть напрям дешу
   з нього, ходьба лишається аналоговою. Клавіатура від цього не змінюється (smoke: хеш реплею з клавіатурним вводом
   = база).
2. `p*_up` / `p*_down` — `InputMap.action_set_deadzone` = тій самій, що в `p*_left` / `p*_right` (зараз 0.3), доки
   Архімед не дасть радіальну. Тоді `dash8_check` має показати діагональ 45°.
3. Підказка `_hint_free`: `LShift dash` → `LShift+dir dash`, `C dash` → `C+dir dash`, `. dash` → `.+dir dash`.
4. Smoke-гард: `dash_dir8` для 8 кутів стіка і для 8 комбінацій клавіш дає ті самі 8 векторів.

### «Напрям + удар» у 3D

Напрям рахується **відносно суперника**: «вперед» — кут між світовим вектором руху і напрямом на суперника < 45°,
«назад» — > 135°, решта — «вбік». Межі — **PLACEHOLDER**, затверджує Арес. Без руху — нейтраль, як у площині.

### Перевірка «жодна клавіша на двох діях»

Python у сесії 2026-10-03 по трьох таблицях вище плюс Esc / Tab / Backspace (`ui_pause`, `debug_toggle_hitboxes`,
`debug_reset` у `game/project.godot`): SOLO 14 дій — 0 конфліктів, SHARED 28 дій — 0 конфліктів, геймпад — 0 конфліктів.
Після реалізації це перевіряє smoke «no key clashes» (Гефест, 0.3-1).

## Тач (план, фаза 4)

Godot 4.7 `VirtualJoystick` зліва; справа: Легкий 64 dp, Важкий/Блок/Стрибок/Гарпун 56 dp,
скіли 44–48 dp угорі справа, відступи 8 dp; деш — кнопка ДЕШ 56 dp + напрям джойстика (§ Деш у 8 напрямках; флік — опція); ульт — контекстна кнопка при
повному метрі. Редактор лейауту (позиція/масштаб/прозорість) — як у Brawlhalla.
Смуга бійців 31–59 % висоти екрана знизу вільна від кнопок: кластер нижче 30 %, скіли й ульт вище 60 %
([[06-UI-UX]] § Розмір бійця на телефоні).
