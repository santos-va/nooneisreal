# Модульний контент і комерційне володіння — пропозиція

**Дата:** 2026-10-05 · **Роль:** T1 · **Статус:** `draft`
**Виріс з:** доручення Santos у [[2026-10-05-Playable-District-Session]]. Це напрям після playable-кварталу, не нова ліцензія й не готовий захист продажів.

## Аудит і погляди

Перевірено `game/scripts/core/GameState.gd`: наразі зареєстровано лише Choko/Skea. У корені checkout файлу LICENSE не знайдено; наявні ліцензійні рішення стосуються ассетів ([[ADR-013-License-Check-At-Release]]). Репозиторій і releases доступні через GitHub connector; зміни visibility/видалення історії цією роботою не виконуються. Поточна зміна кварталу відділяє declarative content від коду, але не є довільним mod runtime.

| Варіант | Наслідок | Пропозиція |
|---|---|---|
| Увесь код і контент під unrestricted open-source ліцензією | Дає широкі права повторного використання; не відповідає наміру окремо продавати право на копію proprietary гри | Не вводити мовчки |
| Комерційне ядро/арт + окремий відкритий SDK і приклади модів | Дозволяє розвивати моди без автоматичної передачі всіх прав на гру | Рекомендований напрям, потребує окремого вибору ліцензій |
| Публічний source-available код із спеціальними умовами | Прозорість коду з обмеженим використанням; це не те саме, що unrestricted open source | Альтернатива після юридичного опрацювання |

Погляди: покупець має грати offline після підтвердження покупки; моддер потребує стабільного API й прикладів; автор має контролювати розповсюдження комерційних ассетів; зберігач saves потребує міграцій; гравець з модами не повинен втрачати дані від невідомого контенту; підтримка має відрізняти чисту й модифіковану збірку. Немає обіцянки технічно невзламного клієнта: код, який виконується на чужому пристрої, може бути змінений. Шифрування пакета не повертає секретність уже оприлюднених байтів.

## Запропоновані межі модулів

- **Ядро:** simulation, save migrations, input, scene lifecycle і validation; API звертається за стабільними IDs, не за шляхами внутрішніх вузлів.
- **Контент:** версійовані описи районів, quests, dialogue, palette, hero IDs. Для початку тільки відомі типи подій/винагород і числові межі; жодних скриптів або довільних файлових шляхів із JSON.
- **SDK:** окремі schema/spec/sample/test fixtures із власною явно обраною ліцензією. Ігрові assets не стають SDK assets автоматично.
- **Завантаження модів:** майбутній каталог `user://mods/` з opt-in, manifest/schema version, ID namespace, source digest і capability policy. Невідомий/хибний мод вимикається з поясненням; core save не переписується до валідації. Це дизайн, поки runtime такого каталогу не реалізовано.
- **Save:** stable hero ID + content IDs + version, з міграціями та поведінкою для відсутнього контенту. Вісім сюжетних героїв — майбутні записи, не вісім вигаданих доступних моделей.

## Купівля й offline доступ

Для майбутнього сервісу можна перевіряти підписаний entitlement-токен: приватний ключ лишається на сервері, клієнт має тільки публічний ключ для перевірки. Випадковий client ID сам по собі не доводить купівлю. Така схема перешкоджає самостійному створенню валідного серверного підпису, але не заважає зловмиснику вирізати клієнтську перевірку; її не описувати як захист від усіх crack-ів.

Перед реалізацією вирішити offline grace/recovery, перенесення між власними пристроями, відмову сервера й мінімізацію персональних даних. Не вводити обов'язковий always-online або hardware fingerprint без окремого продуктового рішення. Зараз не додано ні сервера, ні DRM, ні блокування запуску.
