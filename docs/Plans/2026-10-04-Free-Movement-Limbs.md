# Вільний рух, природна хода та удари чотирма кінцівками

**Дата:** 2026-10-04 · **Роль:** T1 Дедал · **Статус:** `done` — пряме доручення Santos; J/K/M/фізична кома та плечові кнопки підтверджені.
**Основа:** [[Plans/2026-10-04-Comfort]], [[ADR-020-Camera-Continuity-And-Impact]], [[02-Combat-System]], [[05-Platforms-Input]].

## Аудит і погляди

База main1440344 після PR165; гілка `codex/free-movement-limb-combat`. T2/T4: `DuelFrame.to_world` міняє напрямок від лінії суперника, `_walk_free` прив’язує рух до радіуса, `_update_facing` примусово дивиться на ціль. `SkeletalRig` програє walk з фіксованою каденцією, незалежно від швидкості. T3/T2 знайшли вже ліцензовані UAL Jog, Sprint, Crouch та бойові кліпи; нова покупка не є необхідною.

Рух: A — залишити прив’язку до ворога, не відповідає запиту; B — незмінні світові осі, незручно при обертанні камери; C — неперервний симуляційний базис без перевороту знака, зафіксований на час одного жесту руху, обрано. На цій основі камера не передає дані у симуляцію; наступний [[Plans/2026-10-04-Harpoon-Inventory-Ropes]] додає явний записуваний view-basis до вводу для нових жестів після ручного повороту. Відпускання повертає можливість оновити базис; рух не проєктується на коло ворога. CPU зберігає власний напрямок до цілі.

Анімації: A — лише прискорити walk, дає неприродну каденцію; B — використати наявні Jog/Crouch з калібруванням за відстанню, обрано; C — купувати чи генерувати новий пак до перевірки наявного, зайва невизначеність. Удари: A — чотири плечові кнопки з Y-модифікатором здібностей, обрано; B — чотири face buttons, суперечить запиту; C — double tap, неоднозначність і випадкові здібності.

Погляди: клавіатура Mac потребує фізичної коми; геймпад — відповідності ліво/право; два локальні гравці — відсутності колізій кнопок; новачок — явної довідки модифікатора; досвідчений гравець — стабільного руху після перетину; чутливий до руху — збереження camera comfort; обмежена моторика — ціна утримання Y записана, переназначення окремо. Візуальна різноманітність не повинна приховано змінювати hitbox чи damage.

## Кроки та власність

1. T2 A: `Fighter.gd`, `DuelFrame.gd`, новий helper ударів. Людський рух незалежний від позиції одного ворога протягом жесту; facing за рухом, ціль для атаки лишається явною. CPU та legacy light/heavy збережені. Ризик: реверс, застряглий ввід, зміна детермінізму. Перевірка: реальні input events, перетин/обхід цілі, CPU, dash, `make check-playable`.
2. T2 animation: `SkeletalRig`, `RigAnimator`, `ProceduralMotionFallback` за потреби. Jog/Walk за швидкістю, фаза за відстанню, crouch enter/idle/exit, ліві/праві пози ударів із рухом корпусу. Ризик: ковзання стоп, неправильне дзеркало, стрибок пози. Перевірка: фактичні світові точки стоп обох героїв і native послідовності, а не лише імена кліпів.
3. T5: [[02-Combat-System]], [[03-Skills-Framework]]. Standing hand: jab → alternating cross / same-hand bodyhook → uppercut; foot: frontkick / roundhouse / spinkick за кроком. Максимум три normal, нога завершує normal-string; лише підтверджене влучання, не whiff/block. Crouch/air успадковують наявні донори. Frames/damage/boxes — з чинних донорів, варіанти поз не означають зон пошкодження. Нові чотири нормалі — явний виняток із старої межі9 за дорученням Santos.
4. T8 + T2 input: `InputRouter`, `ComfortPanel`, нові inputchecks. SOLO J/K/M/comma; SHARED P1 F/G/Z/B, P2 K/L/N/J без конфліктів старих здібностей. Pad LB/RB руки, LT/RT ноги; X guard; Y+LB/RB/RT — skill1/skill2/grapple, Y+LT без атаки. Ризик подвійної дії при відпусканні модифікатора: маршрут обирається на новому натисканні, тримається до нейтралі; UI fences покривають усі дії. Довідка пояснює chord.
5. T3: джерела/паки/rigcompatibility, без вигаданих цін та ліцензій. T4: незалежний аудит. T7: журнал і wiki. T1: цей план, пріоритети й інтеграція.

## Додатковий запит Santos: гарпун і початок міста/NPC

Гарпун включено в реалізацію: поточна перевірка конуса без снаряда не доводить влучання. Варіанти A — лишити миттєву перевірку, суперечить запиту; B — swept-снаряд після30 кадрів замаху, обрано; C — повний фізичний ланцюг, зайва нестабільність. Зберігаємо14м із чинних даних, заряд витрачається на запуску, перешкода перехоплює політ, підтяжка через наявну кінематику лише після контакту hurtbox. Тримання кнопки зберігає мотузку, нейтраль не змінює довжину, вперед підтягує; відпускання відчіпляє. Погляди: захисник може уникнути кидка; нападник бачить замах; новачок розуміє held/release; геймпад зберігає chord; чутливий до руху не отримує примусового оберту камери; симуляція має обмежену вартість.

T2 harpoon володіє GrappleHook і погодженою передачею Fighter після завершення limb-смуги; T2 animation додає замах корпусом і hanging pose, T5 — правила. Перевірки: промах/укриття/межа дальності, заборона притягування без hit, перерваний замах, утримання/відпускання/нейтраль/reel, відповідність поз і native кадри.

T6 підготував [[Art/2026-10-04-City-NPC-Development]] — передвиробництво п’яти захищених NPC і вертикального міського простору: окремі силуети, сучасне взуття, одяг поза конкретною епохою, аналогові паперові AI-гаджети та різні манери. Це старт розробки за словом Santos, не готові meshes/NPC у грі. Розміри/бюджети — PLACEHOLDER до layout; room Function review перед фінальною композицією. Поточні бойові NPC й арена не підміняються декоративними макетами.

## Наступне уточнення контракту

Розкладку єдиного grapple у кроці4 замінив [[Plans/2026-10-04-Harpoon-Inventory-Ropes]]: Q/Y+RT — ворог, E/Y+LT — паркур, I — skill2; запас Choko7/Skea2 та залишені мотузки. Поточний контракт описаний у GDD05, попередні кроки вище фіксують послідовність реалізації.

## Перевірка та межі

Godot4.7 запускає лише координатор послідовно. `make check-playable`, `make gates`, цільові позитивні й негативні контролі, native contact sheets руху та ударів обох героїв. Дані comfort не змінювати тестами. Новий PR після чистого кінцевого diff, main мерджить Santos.

Це основа розширюваних комбінацій, не обіцянка нескінченної кількості авторських анімацій. Multi-enemy hit selection, online, нова механіка sprint і повний IK м’язів не випливають із цього виправлення. Камера зберігає пріоритет супротивника. Game Development Studio CLI та Higgsfield tools відсутні; Build 3D Game Rooms не створює скелетні анімації. Нові платні генерації не запускалися.
