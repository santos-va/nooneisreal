# Choko: зібрана стійка, меч і перекладання між руками

**Дата:** 2026-10-04 · **Роль:** T1 Дедал · **Статус:** `done` — Santos просить виправити стійку, повернути мечі та видиме перекладання; один активний меч і V/R3 підтверджено.
**Основа:** PR #167, `93471a1`; [[Plans/2026-10-04-Free-Movement-Limbs]], [[Characters/Choko]], [[02-Combat-System]]. Окрема гілка `codex/choko-stance-sword` поверх ще відкритого PR #167; main не змінюємо.

## Аудит і погляди

T2 motion: `_guard_arm` піднімає кисті на0.18/0.26 довжини руки ВИЩЕ плечей, а старий тест вимагає цього; native попередньої сесії підтверджує неприродну позу. T5: канон — окремий смарагдовий меч-шука, золотий кристальний меч ульти; наявні PNG є референсами, не готовими weaponGLB. `RigAnimator` робить меч на правому передпліччі, `SkeletalRig._hide_capsules` приховує його разом із капсулами. `LimbMoves` нині всі руки перетворює на кулакові варіанти, стану руки меча немає.

Варіанти стійки: A — лишити підняті руки й змінити камеру, не усуває дефект; B — нижча асиметрична готова поза зі збереженням опори та нейтральними кистями, обрано; C — купити новий пак до огляду наявних кліпів, зайва невизначеність. Варіанти зброї: A — статично прикріпити до правої руки, не виконує запит; B — авторитетний стан однієї руки та видимий контактний handoff, обрано; C — два мечі, відхилено користувачем. Меш: A — плоска PNG у долоні, не дає читаного об’єму; B — процедурний клинок/гарда/руків’я за наявним референсом, обрано як перевірна основа; C — платна генерація до перевірки масштабу/кріплення, не потрібна цьому виправленню.

Погляди: нападник розрізняє клинок і кулак; захисник бачить початок/кінець передачі без невидимого бонусу до дальності; ліворукий режим симетричний; геймпад R3 не ламає правий стік камери; людина після паузи не отримує випадковий swap; Skea не успадковує меч або іншу стійку; гарпун і скіли не запускають одночасно взаємовиключні рухи рук. Цифри передачі — PLACEHOLDER від T5 до перевірки в рендері, чинні damage/frames/hitboxes не посилюються.

## Контракт і власність

1. T2 motion — `IdlePresence.gd`, цільовий тест стійки та external native helper. Спочатку baseline з/без шару, фронт/бік/три чверті; виправити висоту рук, лікті, кисті. Skea/таз/опора без регресії. Перевірка: `idle_presence_check`, contact checks, native обох напрямків.
2. T5 — GDD02/03: один активний смарагдовий меч, права рука за замовчуванням; нога/вільна рука лишаються ногами/кулаком. Ульта тимчасово використовує золотий варіант зі збереженням власника основного меча. Тривалість/момент передачі явно PLACEHOLDER; interruption до контакту зберігає стару руку, після — нову. Перевірка: state transition tests.
3. T2 gameplay/input — `Fighter`, `LimbMoves`, `InputRouter`, `project.godot`, довідка/тести. V у SOLO, R3 на pad; SHARED окрема неконфліктна пара у GDD05. Початок лише у безпечному grounded стані, під час зайнятих гарпуном рук не можна. Ownership змінюється рівно раз, атака знімає snapshot руки на старті. Pause/hitstop не просувають handoff; reset повертає праву. Скіли/новий гарпун не конкурують із передачею; точне правило переривання ноги/дешу задає T5.
4. T2 weapon presentation — новий helper зброї й руху передачі, `SkeletalRig` integration. Клинок і руків’я прив’язані до фактичної кисті hero; одна видима зброя, без стрибка через весь корпус у момент зміни руки. Різні озброєні/неозброєні удари, нейтральна кисть і видима передача обома напрямками. Узгодити API з gameplay перед правками; motion володіє лише IdlePresence. Перевірка: transform/hand-contact/interrupt tests, actual-input native snapshots.
5. T4 — незалежний аудит механіки/поз і доказів. T7 — журнал/wiki. T1 — послідовні Godot, інтеграція, PR з явною залежністю від #167. Жодних паралельних engine instances.

## Приймання та межі

`make check-playable` і `make gates` на кінцевому diff; додані meaningful checks для обох рук, звичайного удару/кулака, передачі до/після контакту, interruption, paused input, skill/grapple mutual exclusion. Native реальні V/R3 та J/K на герої, фронт/бік/три чверті, не лише source skeleton. Наявні пошкодження й range не змінюємо; це не реалізація всіх майбутніх мечів чи нова купівля анімацій. Mac M3 й фізичний контролер не верифіковані хмарою.
