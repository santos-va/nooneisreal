# Керування, натяг і читабельний ресурс

Дата: 2026-10-04. Архімед: дослідження та пряма реалізація за дорученням Santos «нехай архімед … налаштує». Налаштування не називаємо ідеальним до перевірки фізичним контролером.

## Аудит і погляди

Джерела цього зрізу — `game/scripts/core/InputRouter.gd` (подієві маршрути, buffer, modal fence), `game/project.godot` (спадкові pad X=block, B=dash), `game/scripts/ui/Hud.gd` (фіксовані ресурси), `game/scripts/world/CityHud.gd` (раніше без прицільної підказки), `game/scripts/core/HarpoonAim.gd` (snapshot target), `tools/input/limb_input_check.gd` (синтетичні фізичні події). Перевірено локально Godot 4.6.3; поведінку 4.7/конкретного пристрою не вимірювали.

Три варіанти керування:

1. Лише стара клавіатура J/K/M/, і Y+тригери: сумісність, але права рука покидає мишу; Y змушує великий палець покинути правий стік.
2. Повна заміна схеми на mouse-only і face buttons: коротша схема, але губиться м'язова пам'ять і можливість чотирьох кінцівок на звичайній миші.
3. Додаткові близькі клавіші та необов'язкові mouse aliases; L3 як прямий паркour; окремі dodge/skill dash. Обрано: старі клавіші кінцівок і Y+LT збережені, частий dodge не витрачає signature charges.

П'ять поглядів: новачок потребує видимої конкретної дії біля цілі; досвідчений боєць — чотирьох незалежних кінцівок; гравець із двокнопковою мишею — повної клавіатурної альтернативи; гравець геймпада — правого пальця на прицілі під час зачепу; гравець із втомою кисті — tap-latched підвісу без утримання L3. Додатково: два гравці на клавіатурі не мають ділити mouse aliases, читач слабкого кольоросприйняття потребує слів CRITICAL/REST, а не лише кольору.

L3 може збивати напрям лівого стіка під тиском. Тому це коротке натискання, не утримання; Y+LT лишається альтернативою. Комфорт натискання і mouse middle/side не виміряний фізично. Бічні кнопки миші не обов'язкові. Лівий Alt може перехоплюватися окремими ОС/менеджерами вікон — перевірити на цільовому Mac.

## Чинна карта

| Дія | SOLO клавіатура/миша | Геймпад P1/P2 |
|---|---|---|
| Рух / огляд | WASD / RMB+рух | лівий / правий стік |
| Стрибок, підмотка | Space | A / Cross |
| Ухилення зі stamina | лівий Shift | X / Square |
| Signature dash skill | лівий Alt | Y / Triangle + X / Square |
| Ліва / права рука | J / K, або LMB / MMB | LB / RB |
| Ліва / права нога | M / кома, або Mouse4 / Mouse5 | LT / RT |
| Блок | L або F | B / Circle |
| Skill1 / Skill2 | U / I або R / T | Y+LB / Y+RB |
| Ультимейт | O або C | D-pad Up |
| Гарпун ворога | Q | Y+RT |
| Паркур: зачеп / наступна опора | E | L3 або Y+LT |
| Відпустити мотузку | Z | B / Circle |
| Меч: передача | V | R3 |
| Розмова | G | Y+D-pad Down |

SHARED зберігає старі рух/кінцівки/skill клавіші; dodge C для P1 і крапка для P2; signature dash лівий/правий Alt. Detach використовує лівий/правий Ctrl без спільних клавіш із присіданням. Розмова Y / backslash. Mouse aliases вимкнені. B має єдину InputMap дію block; Fighter у стані GRAPPLE трактує натискання block як detach. Жодного дубля pad binding або винятку smoke guard. Подієвий X ніколи не викликає одночасно dodge та signature dash. Зміна Y під утриманою кнопкою не переобирає дію. UI вимагає нейтралі перед новим вводом.

## Варіанти HUD і рішення

1. Повністю без HUD, лише дихання/колір тіла: атмосферно, але точний запас і CD неоднозначні, особливо в accessibility.
2. Лише кільця навколо персонажа: очі ближче до бою, але закриваються геометрією/ефектами і погано читаються в парному бою.
3. Компактна постійна смуга HP зі швом stamina, короткі назви стану, незмінні skill CD та цільова підказка у світі. Обраний практичний зріз: не приховує критичний ресурс, не вводить ще одну велику панель.

Бойовий HUD додає тонку stamina без дублювання dodge charges; signature dash charges та CD лишаються окремі. HEALTH змінюється на CRITICAL нижче 25% (PLACEHOLDER поріг оформлення, не баланс), STAMINA на DODGE · REST за фактичною ціною ухилення профілю. City card звужений до 390 логічних px, текст 18–20, однорядкове навчання; постійний footer прибрано, завершене навчання ховається. Hooks/stamina/dash доступні, подробиці живуть у Pause/Help. B поза паузою не відкриває меню, а лишається detach/block. Підказка біля цілі розрізняє HOOK, TRANSFER, GRAB ROPE та PREPARE GRAB, читає authoritative candidate та не витрачає ресурс. Рання підказка не обіцяє вже досяжного захвату. Під час прицілювання вгору CityCamera зміщує pivot до плеча (1 м, PLACEHOLDER): поперечний sphere sweep перевіряє бічну стіну, після нього чинний SpringArm продовжує перевірку шляху камери. Це звільняє центр від торса, не обходячи колізії.

## Перевірка і відкриті межі

UI: `city_onboarding_check.gd` 56/0, `match_lifecycle_check.gd` 34/0 (сигнал stamina, словесний REST/CRITICAL, незалежний CD dash). Синтетичні події: `limb_input_check.gd` 227/0, `comfort_input_check.gd` 31/0; `dash8_check.gd` — 8 напрямків SOLO/P1/P2/pad, 0 конфліктів клавіатури без винятків. Нові перевірки охоплюють чотири mouse limb події, відсутність P2 mouse control, L3, X проти Y+X, взаємодію проти crouch і release modifier.

Native `tools/ui/traversal_hud_capture.gd` завершився (`/tmp/nir-traversal-shoulder.log`, Godot 4.6.3, Linux Mesa llvmpipe): capture справді вибрав StreetAnchor2 у (-8, 6.5, 8), reachable=true. Особисто переглянуто `/tmp/nir-traversal-shoulder/city_anchor_cue.png`: лампа й зелена ціль відкриті, герой ліворуч, підказка не перекриває status card. Перший capture мав помилкову ручну позицію камери під SpringArm; fixture виправлено на production reset_view + aim offsets. Проміжний native кадр виявив перекриття торсом; shoulder shift усунув його в перевіреному ракурсі. Runtime після зміни камери — `city_runtime_check.gd` 68/0. Це не гарантія всіх міських ракурсів. Повний інтеграційний check/gates веде координатор; тут не стверджується їх проходження. Фізичні gamepad/Mac/4.7 та оцінка втоми пальців лишаються відкриті.
