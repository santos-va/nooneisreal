# Комфорт аудіо: запас рівня, керування та межі оцінки

**Дата:** 2026-10-04. **Роль:** T3 Архімед. **База аудиту:** `adac26e60f07ec75f0868a6bf49df80eb9b534a9`, до паралельної реалізації налаштувань. Це аналіз маршрутизації й файлів, **не прослуховування** та не вимір акустичної гучності навушників.

## Питання

Що зараз може заважати слухати бій, що реально підтверджене файлами, і що потрібно перевірити перед твердженням «звук комфортний»?

## Джерела та метод

- `game/scripts/core/Sfx.gd:28–41,77–84,144–160`: пул, gain голосу, створення шини SFX, компресор і лімітер.
- `game/scripts/core/UltMusic.gd:27–49,58–80,102–108`: один музичний голос, скидання його gain при запуску, fade та Music → Master.
- `game/project.godot`, `[autoload]`: Sfx створюється перед UltMusic; збереженого `game/default_bus_layout.tres` у перевіреній базі немає.
- [[07-Audio]]: рецепти, попередній синтез, бібліотечні джерела; документ прямо залишає слухове прийняття Santos.
- FFmpeg **7.1.5**: кожний доступний активний `.ogg` або `.wav` декодовано у float32 зі **збереженням частоти та каналів**; якщо є обидва розширення для stem, обрано `.ogg`, як у `Sfx._load_first`. Python обчислює `20*log10(max(abs(sample)))`, RMS і кількість `abs(sample)>=1`. Це sample peak, **не true peak і не LUFS**. Для повторення: `ffmpeg -v error -i FILE -f f32le -` та відповідні interleaved float32 виміри. У cloud артефакт: `/workspace/nooneisreal-env/comfort/audio/decoded-source-stats.json` (не переносний файл репозиторію).
- Спроба прочитати `https://docs.godotengine.org/en/latest/tutorials/audio/audio_buses.html` 2026-10-04 повернула HTTP 403. Зовнішні правила комфортної гучності та психоакустичні твердження **не заземлені** цим брифом. Пізніше доступні офіційні сирці нижче дозволили перевірити API фінального лімітера.
- [Godot 4.7-stable: AudioEffectHardLimiter.xml](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/doc/classes/AudioEffectHardLimiter.xml) та [реалізація, `_bind_methods`, рядки 149–161](https://raw.githubusercontent.com/godotengine/godot/4.7-stable/servers/audio/effects/audio_effect_hard_limiter.cpp), прочитано 2026-10-04: `ceiling_db` (−24…0), `pre_gain_db` (−24…24), `release` у секундах (0.01…3; default 0.1). XML прямо рекомендує Master як місце захисту суми. Це **AudioEffectHardLimiter**, не старий `AudioEffectLimiter`: `threshold_db` тут немає. Сирці й XML узгоджуються.

**Не використовувати як джерело** `decoded-mono-stats.json`: це рання проба із примусовим mono downmix і ресемплінгом, вона змінює піки. Таблиця вище спирається на `decoded-source-stats.json` без таких перетворень.

## Конкретний дефект запасу міксу

На базі немає фінального Master limiter. Навіть якщо припустити ідеальне обмеження SFX до −1 dBFS, одночасна музика з піком −13 dBFS дає верхню оцінку суми:

`20*log10(10^(-1/20) + 10^(-13/20)) ≈ +0.947 dBFS`.

Це **можливість перевищення** для односпрямованих піків, не спійманий у грі кліп. Пік музики й максимальний SFX не обов'язково збігаються. Передано T1/T2: додати ідемпотентний захист фінальної суми або забезпечений запас gain. T1 обрав фінальний `AudioEffectHardLimiter` на Master з `ceiling_db=-1`, `pre_gain_db=0`, `release=0.1`; API перевірене за двома офіційними файлами вище. Реалізацію та runtime-тест цього рішення веде T2, цей бриф їх не засвідчує. Перевірити максимум усіх повзунків; нижчий типовий рівень сам по собі не гарантує запасу на максимумі. Сам limiter не є доказом комфортної гучності або відсутності intersample overs.

## Передача налаштуванням

1. Створювати autoload налаштувань **після Sfx та UltMusic**. Обидва `_ensure_bus` повертаються, якщо шина з потрібною назвою вже існує; попередньо створена порожня SFX позбавила б її compressor/limiter.
2. Збережений music gain застосовувати на шині, бо `UltMusic.play()` скидає gain голосу в 0 dB. Fade лишається локальним до голосу.
3. Незалежні Master / SFX / Music; нуль має давати справжній mute. Обмежити введення до допустимого інтервалу й перевірити повторний запуск.
4. Запропоновані T2 початкові лінійні рівні Master **0.8**, SFX **0.8**, Music **0.6** — **PLACEHOLDER для прослуховування**, не стандарт гучності. Вони зменшують вихід, але не виправляють сам тембр чи повторюваність.
5. Перевірити, що відкриття меню й повторне застосування налаштувань не додає нових шин/ефектів і не змінює ігрові події. Не обривати активний звук просто заради зміни гучності.

## Практичні ризики й прийняття на слух

Комбінації `crit` + удар, стінгер + затухаюча музика, water contacts + звичайний land реально викликаються окремими подіями. Це не автоматично помилки: шари можуть бути навмисними. Чи маскують вони телеграф, чи металевий верх ріже слух, чи повтор стомлює — без прослуховування **не перевірено**. Не видаляти шари навмання.

Сценарій для короткого порівняння Santos на тому самому пристрої й незмінній системній гучності: меню → легкі удари → блок/важкий/crit → деш і вода → ultimate зі стінгером. Порівняти типові налаштування та знижену музику; окремо перевірити, чи ясно чути контакт без опори на екран. Занотувати конкретну подію й варіант файлу, а не «все голосно». Повторити на динаміках Mac і звичних навушниках, якщо вони є. Слухове прийняття, акустичний рівень, довга сесія та фінальний мікс поки відкриті.
