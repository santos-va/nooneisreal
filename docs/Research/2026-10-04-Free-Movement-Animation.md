# Вільний рух і чотири кінцівки: наявні анімації

**T3 Архімед, 2026-10-04.** Питання: чи бракує паків для бігу, присідання та різноманітних ударів, чи спочатку потрібно правильно використати наявні? Дослідження файлів, без запуску рушія, генерації й покупок. Візуальне приймання — окремий крок T2/T4.

- SHA-256 UAL1: `d1cb4537efa4c06a953ca951e5935062f88c2580ac68e45045592d587bddb43d`; UAL2: `ad3ae049c7d3d4846133b59dba6218fdabebe05d3aec646caef6665f6c540684`.
- `docs/Art/Textures-Registry.md:111–112`: обидва **Source**, куплені Santos 2026-10-03, CC0 1.0 за `License.txt` у zip. `tools/fetch_ual.sh` перевіряє відомий префікс/суфікс SHA архівів та наявність CC0 у License перед записом у реєстр. Самі вихідні zip/License у цій сесії повторно не відкривалися; ліцензійне свідчення — чинний реєстр і процедура імпорту.
- `game/scripts/fighter/SkeletalRig.gd`: `HERO_BONES`, `retarget()`, `walk_clip()`, `state_clip()`, `_physics_process()`; `game/data/characters/choko.tres` та `skea.tres`: швидкості, зіставлення атак і часові контакти.
- Попередній [[2026-10-03-Animation-Sources]] описував насамперед **Standard**. Його висновок «немає Kick / BackFlip» не описує теперішні локальні Source-файли. Посилання на каталоги: [UAL1](https://quaternius.itch.io/universal-animation-library), [UAL2](https://quaternius.itch.io/universal-animation-library-2). Сторінки й ціни в цій сесії не перевірялися, нові ціни не пропонуються.

## Що реально вже є

UAL1 містить **120**, UAL2 — **134** записи анімацій, включно з `A_TPose` у кожному; це не 254 унікальні бойові прийоми. Обидва мають 65 суглобів skin.

| потреба | наявні кліпи | тривалість джерела |
|---|---|---|
| ходьба | `Walk_Loop`, у UAL2 `Walk_Fwd/Bwd/L/R` та діагоналі | 1.333333 с |
| біг підтюпцем у 8 напрямках | `Jog_Fwd_Loop`, `Jog_Fwd_L/R_Loop`, `Jog_Left/Right_Loop`, `Jog_Bwd_Loop`, `Jog_Bwd_L/R_Loop` | 0.933333 с |
| швидкий біг | `Sprint_Loop`, `Sprint_Enter`, `Sprint_Exit` | 0.666667 / 0.866667 / 1.666667 с |
| присідання | `Crouch_Enter`, `Crouch_Exit`, `Crouch_Idle_Loop` | 0.833333 / 0.833333 / 2.933333 с |
| рух навприсядки | 8 напрямків `Crouch_*_Loop` | 2 с, лише `Crouch_Bwd_R_Loop` 2.4 с |
| прямі удари руками | `Punch_Jab`, `Punch_Cross` | 0.866667 / 1 с |
| боковий / аперкот | `Melee_Hook` + `_Rec`, `Melee_Uppercut` | 0.466667 + 0.6 / 1.066667 с |
| удар ногою / коліном | `Kick`, `Melee_Knee` + `_Rec` | 1.1 / 0.866667 + 0.233333 с |
| комбінація | `Melee_Combo` | 2.266667 с |

Також присутні `BackFlip`, `JogToFlip`, `KipUp`, `Sword_Aerial_*`, численні `Sword_Light/Regular/Heavy_*`. Самої назви недостатньо для твердження про удар конкретною кінцівкою, висоту цілі чи придатний контакт: це потрібно виміряти на позі.

## Чому купівля паку сама не прибере ковзання

На момент аудиту `SkeletalRig._physics_process()` просуває loop як `_state_frames * delta` незалежно від фактичного переміщення. `walk_clip()` вибирає напрямок, але лише сімейство Walk. У даних Choko/Skea `walk_speed` = 5.6/6.2 м/с; при незменшеній швидкості за цикл 1.333333 с тіло проходить 7.47/8.27 м. Це арифметична ознака можливої невідповідності частоти кроків, **не вимір фактичного ковзання**: вода, прискорення, напрямок і втома змінюють швидкість.

Технічний маршрут для T2: вибір Walk/Jog за фактичною швидкістю; спільна нормалізована фаза для зміни напрямків; просування фази за пройденою відстанню з каліброваною довжиною циклу; перевірка world-space стоп у фазі опори. Перехід у присідання повинен зберігати контакт із підлогою, а не лише замінювати назву кліпу. Величини довжини кроку, швидкісні пороги і плавність залишаються PLACEHOLDER до виміру/візуального приймання.

## Сумісність і процедурні варіанти

Локальні герої `choko_m0.glb` та `skea_m1.glb` мають по 24 суглоби, без пальцевих ланцюгів. `SkeletalRig.HERO_BONES` уже зіставляє Meshy `Spine02 → spine_01`, `Spine01 → spine_02`, `Spine → spine_03`; `retarget()` копіює зміну глобального обертання відносно rest та масштабований рух таза. Новий пак не потрібен для початку: runtime використовує вже наявний ретаргет, а не очікує нового BoneMap у редакторі.

Для чотирьох кінцівок можна перевикористати джерела із дзеркальним відображенням пози й явним обміном лівих/правих кісток. Не слід вважати простий негативний scale усієї моделі перевіреним рішенням: він торкається геометрії/нормалей, а не лише семантики удару. Для кожного варіанта треба перевірити рух потрібної кисті/стопи, опорну ногу, момент контакту та відсутність зміни детермінованого бою від презентаційного шару.

Обмежені адитивні зміни напрямку корпуса, висоти цілі, повернення в стійку й реакції опори можуть розширювати результат. Скелет без пальців не створить окрему анімацію стиснення кулака. Реальні м'язи й необмежена генерація анатомічно правильних атак із назв кісток **не реалізовані**; для них потрібні додаткові дані й окреме приймання. Новий контакт `Punch_Cross` або `Melee_Uppercut` не можна запозичити з Jab тільки через схоже призначення.

## Висновок і відкриті перевірки

Для поточного зрізу достатньо наявних ліцензійно зареєстрованих Source-паків. Наступний пак має закривати конкретну прогалину після перегляду цих кліпів, а не дублювати ходьбу й удари. KayKit/Mixamo/Rokoko не завантажувалися й не допущені цим брифом; попередні дослідження не замінюють перевірку ліцензії нового архіву для публічного репозиторію.

Відкрите: замір фази опори на героях, перевірка дзеркальних кінцівок і контакту нових ударів, crouch-переходи з реальними стопами, відео руху з напрямками та переходами. Статичний кадр і headless-сентинел не доводять природність ходи. Доступність Higgsfield та game-dev CLI перевіряє T1; цей бриф не обіцяє підключення чи генерацію через них. Blender може бути інструментом авторського редагування після визначення конкретної прогалини; нових Blender-ассетів у межах цього дослідження не створено.
