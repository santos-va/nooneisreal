# Аудит «Нижньої позначки»

2026-10-05 · T4 Феміда. **Фінальний вердикт: GREEN у перевіреному обсязі — save chain, input, фізичний маршрут, світло, native UI та інтегрована батарея.** Scope — один наступний епізод, наземна архівна галерея, спрямований ліхтар і відбиток плити. Це не прохід у катакомби та не завершення основного розслідування.

## Початковий preflight і джерела

Особисті `git status --short` та `git log -3 --oneline` підтвердили чисту початкову базу `6c08328`, merge PR #180. GitHub CI в цій смузі T4 окремо не перевіряв. Прочитано актуальні `CityStory.gd`, `CityWorld.gd`, `CityHud.gd`, `CityNpcDirector.gd`, `CityJourney.gd`, `CityMaintenance.gd`, `CityLayout.gd`, permanent story checks та approved [[2026-10-05-Lower-Mark-Expansion]]. План містить три альтернативи й різні погляди, включно з несправним диском та доступом обох героїв.

Перший CityStory навмисно дозволяє completed лише в пам'яті після невдалого збереження. Тому `stage()==completed` не є достатнім prerequisite. Чинна одноразова NPC пам'ять уже вимагає `save_enabled && save_ok`; наступний епізод має так само розрізняти виконане в поточному сеансі й надійно збережене. Старий v1 schema суворо містить п'ять полів на героя; окремий successor документ уникає непомітної зміни цього контракту.

На початковій базі HUD мав один сюжетний провідник та persistent guide_selected; completed перший епізод ховав його кнопку. Перед інтеграцією зафіксовано вимогу одного effective selector для title/hint/target, збереження старих фактів у журналі та ручних errand/OFF; фінальне виконання перевірено нижче. NPC topics не можуть самі відкривати нову главу. Перший shortcut лишається наслідком тільки першого story.

NW roof і clock tower мають суцільні колізійні коробки. Approved scope лишає їх незмінними: галерея на y4, без нового checkpoint або підземного проходу. Це усуває потребу ламати основу, але не замінює перевірку обох старих маршрутів і corridor x≈−16.

## Незалежна матриця приймання

| Межа | Негатив і позитивний контроль |
|---|---|
| Prerequisite | Відсутній, corrupt, старіший stage, failed write, disk=false або completed іншого героя не дають durable successor; валідний збережений completed того самого героя дає явне прийняття |
| Orphan successor | Валідні нові bytes зберігаються при недоступному predecessor; effective lamp/copy/доступ вимкнені. Відновлення prerequisite повертає точний новий прогрес без повторної NPC винагороди |
| Новий save failure | In-memory дія не створює майбутнього durable NPC факту; corrupt bytes не перезаписуються, старі story/district/NPC схеми не переписуються випадково |
| Ліхтар і відбиток | До правильного освітлення перша копія неможлива; після копії поворот убік не стирає історичний факт. `copied=true, lamp_aligned=false` легітимний, completed потребує accepted+copied |
| Реальний input | Mapped-key callback, чужий/nested UI owner, range/height/LOS, stale episode offer і NPC priority. Held-key перевірка без restart/reset між цілями, з позитивно підтвердженим утриманням |
| Світ і маршрут | Обидва герої реально доходять до галереї; старі court/bridge/checkpoint маршрути працюють. Native показує світло на плиті, різницю двох положень, видиму копію та чесну підказку |
